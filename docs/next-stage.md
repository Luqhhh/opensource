# 下一阶段需求基线与首期实现

本阶段把 ExampleProof 定位为开源项目教程质量分析与改进工具，目标是提升读者学习效率及实际使用效率。项目级分析与已有 Python 隔离验证共享只读输入、证据来源和人工审阅原则。目标尚未通过读者实验验证。

## 模型与输入

- DeepSeek 提供无需本地部署模型的 API 入口；保留本地 Ollama。模型供应商和上下文策略分别选择，不把检索方法绑定到某一家模型。
- `analyze OWNER/REPO` 或 `analyze https://github.com/OWNER/REPO` 为 GitHub 入口；已有本地目录直接使用。目录存在时优先识别为本地；不存在的绝对路径、`./`、`../`、`~` 路径会报错而非触发下载。
- GitHub 先解析指定 ref（默认 HEAD）到 commit SHA，再下载该提交的 ZIP。只支持公开仓库；暂无 GitHub Token、私有仓库、子模块及 Git LFS 内容获取。ref 用 `--ref` 指定，报告记录 commit。
- 本地项目只读取，不执行 Git 命令、安装脚本或仓库源码；按读到的原始字节记录文件 SHA-256。当前读取不提供并发修改下的原子快照保证。
- 项目级 `analyze` 默认 `deepseek-flash`＋规则检索（`--context-strategy lexical`）；需配置 `DEEPSEEK_API_KEY`。`compare` 默认同一 Flash 模型，对照 lexical 与 ai。`--provider ollama --model MODEL` 可切换本地服务，`--context-strategy ai` 显式启用 AI 选择。
- `analyze --static` 仅做静态检查，无需密钥，不发起模型调用；不可与 `--provider`、`--model`、`--endpoint` 或 `--context-strategy ai` 同用。缺少密钥或服务失败均报错；不自动切换服务、静态模式，不自动重试付费请求。底层 `analyze_project(client=None)` 仍为静态库接口；旧 `repair` / `benchmark` 维持原有默认和回放语义。
- DeepSeek 使用官方 HTTPS API；`DEEPSEEK_API_KEY` 通过 Authorization 头发送，不写入推理证据。已知密钥还会从服务返回正文及错误中替换为 `[REDACTED]`。本轮按用户指定选用 `deepseek-flash`，默认配置也使用 Flash；模型名仍可配置，不锁定服务的长期模型名称或价格。
- Ollama 保持回环地址、禁用环境代理和重定向。DeepSeek 与 GitHub 的外部 HTTPS 请求遵循用户环境代理配置，禁用 HTTP 重定向。

## 项目级分析范围

输入由 README、教程目录、示例、源码和依赖声明共同构成，不要求手动挑选孤立 README。Markdown、MDX 和 RST 被识别为文档；Python 源码使用现有 AST 单元索引，其他文本源码按行分块。RST 当前未解析专用指令树；多语言源码当前未做类型或调用图分析。静态分析没有执行任何项目代码。

当前静态规则仅检查 Markdown/MDX 中可识别的本地行内链接目标，排除围栏代码中的文本；不验证外链、锚点、引用式链接、图片或站点根路由。不存在的目标是当前快照中的观察，静态网站路由仍需人工核对。已知因为大小或符号链接而未复制的 GitHub 路径不作为缺失链接报告。

模型分析的质量维度包括：

| 维度 | 读者遇到的障碍 | 所需证据示例 |
| --- | --- | --- |
| 前提条件 | 版本、依赖、账号或配置准备不明确 | 安装章节、依赖声明、配置读取代码 |
| 步骤顺序 | 使用某项能力时还没有完成必要准备 | 教程章节、示例、初始化入口 |
| 概念解释 | 关键参数或中间结果含义不清 | 教程正文、函数签名、docstring |
| 一致性 | 教程描述与当前 API、配置或示例冲突 | 两处原文及其文件位置 |
| 错误处理 | 读者失败后缺少可执行的排查指引 | 错误条件、异常说明、使用章节 |

每条 AI 建议必须引用已发送的证据 ID；程序解析原文件及行号，不接受模型提供任意路径。引用有效仅说明证据来自原文，仍需人工判断其是否支持该建议。无有效证据的建议会被丢弃并记入警告。没有出现在摘录中的信息不能据此判定为全项目缺失。

输出包含 JSON 审计数据、独立 HTML 报告和待审阅的建议 Markdown。最多接受两个文字修改建议，只有精确匹配且唯一的 Markdown 正文完整段落才进入 `suggestions.patch`；不接受部分词语替换、未知证据 ID、代码块、缩进代码、断言、标题、列表、表格和 HTML 修改。行内代码和链接必须逐字且按原顺序保留；重叠修改会被拒绝。补丁保留 BOM 与换行格式，记录接受和拒绝原因，绝不自动应用。RST/MDX 当前只分析，不生成文字补丁。

文字补丁始终标记 `unverified_prose_edit`，不将模型新增文字或断言作为独立行为证据，也不导出为 `verified.patch`。已有 `repair` 链路仍在独立检查通过后生成文档代码块补丁。合成夹具、候选回放和实时模型调用使用独立的来源标记；实时调用的质量结论仍须单独评审。

## 两种上下文方案

| 方面 | AST + 关键词直接选择（lexical） | 静态索引 + AI 选择（ai） |
| --- | --- | --- |
| 选择方式 | 从标题、符号、正文词项及文件类型排序，交错保留文档和源码候选 | 对同一候选集的有界摘要做一次模型选择，再读取对应原文 |
| 优势 | 稳定、易审计，无额外选择调用 | 可按读者任务判断关联，有机会找到词面关联较弱的前提 |
| 局限 | 同义表达和隐含跨文件关系容易遗漏 | 候选之外的内容仍然不可见，可能误选且增加成本 |
| 模型调用上限 | 仅分析阶段 1 次 | 选择 1 次、分析 1 次 |
| 失败处理 | 保留静态结果和错误记录 | 选择失败或 ID 无效时显式回到 lexical，仍使用同一服务 |

`analyze` 两种策略复用 `_terms` 与 `_units`，增加文档标题、文件角色与项目级候选排序。中文标题和正文使用标准库实现的字对分词，不增加第三方分词依赖；`go.mod`、无扩展名的 LICENSE/NOTICE/COPYING 也可发现。候选集先交错保留文档与源码，再补齐到上限。它们不是既有 `semantic-v2` 修复检索器的完全同一排序；旧实验结论不能直接用于新分析器。

当前每次项目分析只有一个有界上下文，不做递归代理式探索。候选最多 40 个；AI 可选 1–12 个已展示的 ID，并保留一个教程锚点。最终证据数组按序列化 JSON 字符数限制（含标签、分隔符及原文），默认 12000 字符，可配置 2000–48000。AI 选择摘要数组也受同一字符上限约束。系统提示词、覆盖范围字段和服务协议额外占用 token；这不是整次调用的 token 上限。每次生成最多 2048 token。

报告记录所选原文、候选 ID、请求及响应、失败正文、UTC 时间、耗时、各阶段 token 和合计；任一请求的用量未知时，对应总量为 null。失败调用也计入请求数，服务已返回的有效用量会保留。选择成功不保证分析成功，也不保证更好的质量。

## 输入和运行边界

- GitHub ZIP 下载最多 20 MB，展开大小合计最多 64 MB，最多 20000 个归档条目。先校验所有路径，再手动复制合格普通文件；拒绝越界和重复路径，不创建归档符号链接。
- 本地发现最多访问 20000 个文件条目；最多索引 1000 个 UTF-8 文本文件、原始字节合计 8 MB、单文件 256 KB。上下文最多 4000 个片段，每片段不超过 80 行及 4000 字符；超长单行会省略并标记覆盖不完整。
- 排除隐藏路径、测试目录、历史 evidence、构建产物、依赖副本及已知包含 evaluator 检查的 `exampleproof.json`、`metadata.json`、候选 JSON。按名称过滤 secret/credential/password/token/private-key 及证书私钥。文件名过滤无法识别所有内嵌凭据，云端分析前需检查项目内容。
- 覆盖范围、文件摘要、跳过原因以及 GitHub 快照中未复制的合格路径写入报告；“未发现问题”不表示完整覆盖或教程正确。
- 输出必须在被分析项目目录之外，且使用全新目录，避免改写输入或旧证据。
- 原有 Python 执行仍只通过 fail-closed Bubblewrap runner；无法隔离就标记 blocked，绝不回退宿主执行。当前 `analyze` 不执行，原 `scan/check/repair/benchmark` 仍接收配置指定的本地项目路径。

## 使用与退出状态

```sh
python3 -m exampleproof analyze OWNER/REPO --ref COMMIT_SHA \
  --provider deepseek --context-strategy lexical --output /tmp/quality-lexical

python3 -m exampleproof analyze OWNER/REPO --ref COMMIT_SHA \
  --provider deepseek --context-strategy ai --output /tmp/quality-ai

# 已有配置项目的 DeepSeek 修复；行为验证要求与 Ollama 相同
python3 -m exampleproof repair /path/to/configured-project \
  --provider deepseek --repair-policy semantic-v2 --output /tmp/python-repair
```

`analyze` 退出码 0 表示完成且没有处理警告，发现问题本身不导致失败；2 表示输入／配置错误或存在模型、解析、证据引用等警告。模型失败时仍可保留静态报告。不会把服务错误计为教程质量差，也不会把零发现视为检查通过。`repair` 等已有命令保留原状态含义。

## 下一阶段验收与对照协议

`compare` 已提供探索性成对运行入口：先一次性读取项目并冻结文件内容、原始字节摘要、片段及静态观察，再保存 `snapshot.json`、`protocol.json` 和实现源码归档，之后顺序运行 lexical 与 ai。两组不会重新读取正在变化的本地项目。快照 JSON 记录 BOM 元数据及未经换行归一化的正文，可重建输入字节以核对摘要；LICENSE/NOTICE 等也随合格输入保留。输入可能包含用户内容，分享前需检查授权范围。

每组分别输出分析报告和待审阅文字补丁，汇总报告展示实际策略、回退状态、上下文交集、分阶段用量、失败及警告；独立评审模板中的正确性、证据支持度和可操作性初始为 null。它不自动选出质量优胜者。`compare-audit OUTPUT` 无模型调用，检查快照摘要、归档源码、片段及引用原文、模型和提示词、请求用量及两组汇总一致性；只保证记录内部一致，不能证明服务真实性、建议正确或学习效率提高。输出缺失或篡改时返回失败。

```sh
python3 -m exampleproof compare OWNER/REPO --ref COMMIT_SHA \
  --provider deepseek --model deepseek-flash --output /tmp/paired-comparison
python3 -m exampleproof compare-audit /tmp/paired-comparison
```

`compare` 成功完成且无警告时退出 0，部分失败或警告退出 2，并保留已生成证据。`compare-audit` 一致性核对通过退出 0，否则退出 2。

实现验收覆盖输入只读、公开 GitHub 获取、不同输入源的一致索引、云端凭据保护、Ollama 兼容、上下文预算、无效引用拒绝以及原有隔离验证流程。接口模拟与合成夹具只验证工程行为；公开仓库静态 smoke 只验证真实网络输入链路；两者均不代表实时模型质量结果。

效果评测需在首次调用前冻结项目 commit、教程任务、人工标注、模型、提示词、生成参数和成本预算。比较新项目级 lexical 与 ai 时，保持同一输入、候选集及分析提示词，单独记录选择阶段的成本。相同最终上下文字符预算不能称为相同总 token 成本；额外进行相同总 token／费用预算的比较，分析实际输出和失败调用用量。既有 v0.1 修复器仅作为范围不同的历史参考，不混算成功率。

人工评估问题准确率、遗漏率、证据支持度、建议可操作性，记录延迟、总请求和 token。学习效率与实际使用效率需通过读者任务验证，例如首次运行完成率、任务耗时、求助次数和后续使用任务完成率。自动检查、模型新增断言和模型自评分不能替代这些结果。录制候选回放、合成夹具、历史兼容性重现、实时模型结果分别报告。
