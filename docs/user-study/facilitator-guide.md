# 源途 · RepoPath 试用主持人手册

按相同流程观察真实学习者。优先记录具体行为与原话，避免引导受访者肯定产品。参与者只拿到受访者说明；本手册与检查参考由主持人保管。

## 准备环境

使用交付包中的源码或安装包，记录作品提交号、Python版本、浏览器、项目commit、模型模式。需要AI时使用主持人自己的服务配置，不向受访者收集密钥。

```sh
# 在已安装源途的环境中启动，每人换一个目录
repopath learn --data /tmp/repopath-reader-P01 --port 8765
# 无模型时明确记录基础路线模式
repopath learn --provider none --data /tmp/repopath-reader-P01 --port 8765
```

Windows阅读与问答可以使用本机 Python；运行示例使用预先准备的Linux/WSL和Bubblewrap。先运行 `repopath doctor --json`，再由主持人在隔离入口测试项目可导入。禁止宿主执行回退。

TinyDB适合字典与条件查询入门，Schedule适合函数与回调入门。若已熟悉其中一个，优先分配另一个；两者都熟悉时记录熟悉程度，不当作陌生项目入门。

## 开场与帮助

开场说：“今天想看这个工具是否容易理解。请按自己的习惯操作；不顺利时直接说出来。你可以随时停止，我们不会评价你的编程能力。”

确认同意选择，给出P编号，记录项目熟悉度。不提前展示任务答案。观察不知道点哪里、任务表述不清、引用打不开、回答不能帮助继续、运行受阻、保存后找不到记录等事件。

卡住3分钟后询问是否需要帮助。记录实际帮助程度：H0无帮助；H1重复目标；H2指出界面入口；H3提供项目API或代码线索。提供代码线索后完成记为“协助完成”。不要代操作补成独立完成。

网络、模型服务、沙箱或主持人准备问题记为“环境受阻”；用户主动停止记为“退出”。保留所有过程。

## 任务观察参考

| 任务 | 可观察的完成表现 | 区分情况 |
| --- | --- | --- |
| 导入与定位 | 创建项目，指出下一步，打开相关原文 | 主持人代导入不计用户独立完成 |
| TinyDB A1 | 两条给定记录已保存，只查询出未完成记录，找到原文 | AI说完成或勾选不代替输出 |
| TinyDB A2 | 同一完整运行中关闭重开后仍有两条记录，能解释临时文件边界 | 内存数据库不能代替文件持久化 |
| Schedule B1 | 两任务有不同标签，有界执行显示两个输出，找到原文 | 无限循环超时与时区依赖分别记录 |
| Schedule B2 | 取消water后只保留stretch，第二次只显示伸展，能解释注册与执行 | 清空全部任务不满足目标 |
| 恢复学习 | 保存后关闭页面，重开找到任务与笔记 | 主持人帮助后完成记明级别 |

检查参考由开发助手编写；实际判断由主持人观察记录，不称为独立模型评测。TinyDB文件在这次隔离会话内有效，结束后删除。

## 记录文件

- `observations.csv`：每个实际任务一行；状态independent、assisted、incomplete、blocked、withdrawn。
- `questionnaire.csv`：每名实际参与者每题一行；评分1–5或NA。
- `interviews.csv`：每条实际反馈一行，记录匿名引用许可；未授权原话保存在私有记录。
- `external-reproduction.csv`：由未参与开发的人照安装说明复现后填写；自动运行不填成外部复现。

CSV为UTF-8；Excel用“从文本/CSV导入”。将公式符号开头的原话作为文本导入。建议原话保存在独立文本笔记中，表格记录其编号。

## 结束与整理

先独立回答五题，再问：哪一步最有帮助？哪里最想退出或换工具？AI回答怎样影响下一步？只能改一处，会选什么？不要问“是不是比普通AI更好用”。

保留相反意见和环境故障。按“阻碍任务、增加负担、改善建议”整理问题，写出界面位置、原话、拟改动作和回访状态。小样本体验不推断普遍效率提升。
