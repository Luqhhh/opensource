## 二、两人独立复现的缺陷

### 1. 步骤引用锚在文件头注释，与任务要求不对应（核心）

- P01：「它指向的前五行只有注释……展开操作说明、请求提示后，还是不知道具体怎么安装。」
- P02：第一步「准备运行环境」，点开是 `__init__.py` 第 1–4 行「只介绍这个库的用途」；「展开操作说明，也只有『按原文完成准备』」。
- 两人的修法一致：**让每一步直接定位到相关原文**；P02 补充「找不到时明确告诉我缺少这部分资料」。

这不是"引用不准"，而是**引用与任务语义脱钩**：任务要求"准备环境"，引用给出的却是库的自我介绍。对以"原文引用"为核心卖点的作品，这是核心链路失效。

### 2. 导入失败后已填表单被清空

P02 明确观察到：从 GitHub 切换到上传 ZIP 后，**学习目标被清空**，需重新填写。P02 把"保留已填写的学习目标"列为改进项之一。

### 3. 导入失败提示不可操作

- 超时与路径不安全共用同一标题「导入未完成」；
- 提示列出"地址、公开访问权限、网络"三种可能，不区分是哪一种；
- 「重新导入」重跑同一动作，不提供替代路径（如切换 ZIP）。

P01：「不知道重来时该改什么。」P02：「让导入失败提示给出明确、可执行的下一步。」

### 4. 「操作说明」与「请求提示」在 AI 关闭时为空转

P02 展开操作说明只得到「按原文完成准备」这类同义反复；P01 问安装办法未获具体回答。
**限定：本次均为 AI 关闭模式**，问答能力不可用，此现象不构成对模型能力的评价，但说明关闭 AI 时缺少有意义的降级文案。

### 5. 阅读展开状态未纳入恢复

P01：重开后步骤恢复到第 2 步（正确），但此前展开的全文折叠回初始状态，需重新点开。
