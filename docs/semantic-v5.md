# 参数迁移与候选排序：semantic-v5（2026-10-19）

在 v4 的源码接口候选之外，v5 增加函数调用参数迁移。公开执行出现 TypeError 时，若实际选中的源码中存在唯一、完整的函数签名，工具可以生成有限的完整参数方案，由模型选择，随后继续通过原来的检查。默认策略仍为 legacy。

## 能做什么

- 支持参数顺序变化，以及普通参数变为仅限关键字参数。保留原来的函数、输入表达式和其他代码；每个输入仅使用一次，并保持求值顺序。无法保持顺序的仅限位置参数方案会被排除。
- 从当前源码签名最多探索 256 个分配，向模型提供最多八个完整方案。根据同一函数中 `iter`、`len`、`range`、序列重复和字符串分支等静态使用线索排序。线索不是类型证明，可能受动态绑定影响；方案仍由原检查决定是否通过。
- 对缺失接口，优先考虑与缺失名称有共同词、或属于实际报错接收者的候选，其他所属类的候选仍保留。候选可附选中源码中的简短原文说明；不编写项目专属的替代答案。
- 支持普通函数、模块别名和能够静态确认所属类的方法；源码定义不明确、星号展开、可变参数或缺少实际签名时回到原有修复路径。原断言内部的调用不进入参数改写。
- 多处调用依次报错时，可从最近一次实际执行的候选继续修复。失败参数方案不会反复执行；整体仍受原来的调用次数限制。
- 参数方案只是建议，不能保证语义正确。原断言、独立行为检查、隔离执行和补丁应用后的复查继续执行；不会用模型新增的断言代替独立检查。

参数迁移不读取隐藏检查、预期输出或参考补丁，不在宿主上导入项目或求值表达式。JSON 结构、编号和内容仍做本地验证；服务错误与不合格式的候选分别记录。普通接口替换继续沿用 v4。

主要源码摘录仍按标签与原文合计不超过 4800 字符；参数计划、使用线索与候选合计，或接口候选及其说明，按 JSON 序列化不超过 1200 字符。计划中的源码位置可在冻结输入中核验。超出范围或预算时回到原有修复路径。

## 使用

需在 Linux/WSL 中准备 Bubblewrap 及本地 Ollama。没有新增运行依赖、模型下载或系统服务。

```sh
python3 -m exampleproof repair examples/tutorial \
  --model qwen2.5-coder:1.5b --repair-policy semantic-v5 \
  --max-attempts 3 --model-timeout 180 --output artifacts/live-semantic-v5
```

v5 仅用于实时推理，不能与 `--proposals` 回放混用。输出目录应新建，工具只导出补丁。

## 已完成的开发过程

第一轮让模型直接返回参数名称到输入编号的映射。273 项工程测试通过，但 1.5B 模型经常重复使用编号；完整开发回归 v5 为 14/18、v4 为 15/18。第二轮改为完整方案选择，增加源码原文说明，276 项工程测试通过；开发回归仍为 14/18 对 15/18。这两轮均未证明整体提升，记录保留。

第三轮增加源码使用线索、名称及接收者排序后，279 项工程测试通过；完整开发回归 v5 为 **18/18**、v4 为 **15/18**，正常对照均为 **9/9**，请求分别为 **28 / 33**。每类缺陷均三种子通过，包括之前失败的 grouper 参数迁移。

每轮均另行重测历史 Mistune、Werkzeug 案例；三轮两组均为 **0/12**，正常对照均为 **6/6**。这些涉及多步骤构造、渲染和状态修改的迁移问题仍未改善。它们是历史案例的回归重测，不能重新包装为新的留出测试。[全部迭代与原始证据](evidence/semantic-v5-1p5b/README.md) 保留前两轮退步记录。开发集改善不能估计未见项目成功率，也不把工程测试通过数当作模型修复率。

修复生成、协议验证和静态分析代码由 AI 辅助编写；团队人工审核尚未完成。
