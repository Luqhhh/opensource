# 1. 问题、用户与目标

开源项目读者需要从教程中理解配置前提、运行顺序和 API 行为。维护者需要区分有原文依据的改进、模型误报，以及仅能运行却改变原任务的候选。例证面向教程作者、维护者和学习者，提供项目静态分析与有限任务验证；学习效率和维护成本收益尚未通过用户研究证明。

项目当前有两条互补流程：项目级教程分析读取文档、源码及依赖声明，提出带证据引用的建议；Python 任务验证通过只读输入、固定检查和隔离执行判断明确候选是否完成原任务。前者不执行项目代码，后者需要 Linux、Bubblewrap、系统 Python 和明确选定的纯 Python 源码，不自动安装依赖。

# 2. 已实现的工作流程

| 环节 | 当前实现 | 输出与限制 |
| --- | --- | --- |
| 输入 | 本地目录或固定 GitHub 提交，过滤和大小上限，静态 AST 索引 | 快照、来源与摘要；超出范围不代表项目缺失 |
| 教程分析 | DeepSeek Flash 或本地 Ollama；默认 lexical，ai 可选 | 原文引用、建议、HTML/JSON；建议未经独立质量验证 |
| 补充检索 | iterative 按模型提出的路径、符号或文本缺口搜索冻结索引 | 有界轮次、停止原因与逐轮证据记录，不执行模型命令 |
| 修改提案 | Markdown 正文精确编辑；task-improve 将已有建议和固定任务连接 | 仅导出候选；代码、断言、REPL 输出与 RST 指令受保护 |
| 任务验证 | task-check 支持 Markdown Python 和有限 RST Python/pycon | 原版失败、修改通过、临时应用补丁复查通过，才生成待审阅补丁 |
| 评测与归档 | 冻结协议、开发/留出分离、候选回放/实时推理分离 | 原始请求、失败、token、SHA 与许可证；不以一致性审计代替正确性 |

`task-improve` 绑定分析摘要、建议序号、文档摘要和调用者提供的任务合同。先验证原版，再请求一次候选并调用既有验证器；原版已通过或隔离受阻时不调用模型。候选不能改合同，模型新增断言不能作为独立检查。它不是通用安装修复器，也不支持任意 RST/MDX 结构编辑。

# 3. AI、检索与工程设计

模型用于分析原文、提出检索缺口和文档候选；判断依据来自原文、既有断言或调用者冻结的行为检查。教程模式使用 DeepSeek 官方 API 或本地回环 Ollama；新云端请求须先审阅脱敏清单并显式确认，任务检查正文和参考答案不进入模型请求。自动脱敏是启发式，仍需人工检查。

lexical 通过 AST 与词项选择原文，ai 增加一次摘要筛选；iterative 可搜索初始候选之外的合格索引。三者都只处理有界输入。新增累计输入＋输出 token 停止阈值，未知用量停止追加调用；在途请求可能超出阈值，不能称为计费硬上限。可选 POSIX 主线程墙钟时限能中断阻塞请求；不支持时明确停止。必要证据覆盖须有独立标注，无标注时保持未知。

应用层实现与配置在本仓库开发，使用生成式 AI 辅助，没有训练基础模型。Python 标准库承担核心实现，Python 运行依赖为空；Bubblewrap 是执行边界，模型与第三方库能力不归为自研成果。Sybil 等已有工具提供文档测试能力，本项目探索将原文诊断、固定任务检查和审阅补丁相连的流程，尚无竞品受控效果结论。

# 4. 已完成的证据与结果

## 4.1 项目教程真实模型对照

2026-10-19 的 TinyDB、Schedule、Humanize 固定快照实验比较 Flash/Qwen 7B × lexical/ai，每组两次，共 24 次分析、36 次正式模型请求。下表的“支持”来自助手原文核对，不是独立人工准确率；耗时取当次具体部署的请求平均值。

| 组合 | 建议 | 有支持 / 部分支持 | 无支持 / 不可判定 | 平均请求秒 |
| --- | ---: | ---: | ---: | ---: |
| Flash + lexical | 33 | 14 / 9 | 10 / 0 | 3.80 |
| Flash + ai | 35 | 8 / 20 | 7 / 0 | 5.41 |
| Qwen 7B + lexical | 36 | 0 / 10 | 26 / 0 | 19.07 |
| Qwen 7B + ai | 36 | 0 / 12 | 22 / 2 | 22.09 |

四组均未导出被接受的文字补丁。Flash 的 ai 组累计 token 从 lexical 的 27094 增至 50109，有支持建议数减少；本次记录支持保持规则检索默认，不证明模型的一般排名或等成本效果。详细协议、评阅修订与限制见 `docs/factorial-experiments.md`。旧单项目探索的有效及证据定位失败记录分别保存，未混入这 36 次请求。

## 4.2 TinyDB 首次运行任务

固定 TinyDB 4.9.0 提交 `edff96ae`，任务是在空的可写目录复制 README 首个示例，保留两条记录并关闭重开验证持久化。原文占位路径导致 FileNotFoundError；助手编写的相对路径及说明候选通过固定检查和补丁复查，仅改用内存数据库的合成负例被拒绝。

任务要求在候选构建前冻结，但二者由同一助手编写，不是独立人工标注。熟悉占位路径的读者可能不会遇到障碍。本轮新 task-improve 入口复用上述诊断和候选完成工程回放，模型请求为 0；不增加实时模型成功样本。安装、完整文档渲染、用户效率及上游采纳没有结果。

## 4.3 历史 Python 迁移验证

历史 v1 包含 TinyDB、more-itertools、MarkupSafe 迁移及三组冻结对照。v2 开发集有六个失败、三个健康案例；旧运行时同检查 9/9 通过，参考候选修复 6/6，九个格式合法的错误候选均被语义检查拒绝，其中八个显示输出仍相同。这是检查器及回放证据。

v2 两次开发各 52 次请求，五组预算内均为 4/6。另行准备的 Mistune/Werkzeug 留出共四个失败、两个健康案例，三个种子，180 次请求；五组失败案例运行均为 **0/12**，健康对照各 **6/6**。source_v2 输入 token 比 legacy_source 少 40.32%，没有成功修复成本或反馈收益可报告。开发/留出、历史/当前版本、合成/回放/实时结果不能合并为一个成功率。完整失败、采集边界及有限检查盲点保留在 `docs/evidence/semantic-v2-20261013/`。

# 5. 新任务评测与交付检查

本轮准备 python-dotenv v1.1.0 和 platformdirs 4.3.8 两个未参加此前教程对照的固定项目，四个任务覆盖配置优先级、无副作用读取、Linux 示例和目录创建。任务、必要证据及验收条件由助手起草，独立人工评阅待完成，不能称为新模型效果或盲测。

新评测入口在人工确认冻结协议前不调用模型。lexical 与 iterative 使用同任务、同范围、同候选排序和字符上限；分别记录请求、实际 token、耗时与跨度覆盖。人工评阅逐条判断建议并映射完整 gold 问题清单；缺少评阅时支持率、问题召回率均为 null。读者完成率和耗时需另录观察，不用机器检查替代。

发布检查已改为动态源码清单，核对 wheel/sdist/安装目录中的模块字节、许可证及仓库外入口。旧固定模块数量断言已移除。既有实验与失败记录归档到持久交付目录，逐文件 SHA 及压缩包摘要可离线复核；归档完整性不表示外部认证或完成发布。最终本机验证结果见 `docs/delivery-validation.md`，不能代表远端 CI 状态。

# 6. 安全、资源和权属

原项目保持只读，补丁只在一次性副本应用。沙箱无法建立时停止，绝不在宿主执行项目片段。示例与检查仍共用 Python 进程，不能抵御任意恶意程序篡改状态；有限任务检查不证明一般语义等价。报告包含选定原文，发布前需检查秘密、个人信息和授权。

第三方资源版本、来源、许可及自主边界见附件。AI 辅助覆盖实现、测试、任务草稿和文档整理，自动验证不等于团队人工审核。成员分工、具体辅助服务档案、生成内容权利及共同权利人授权须由团队确认。
