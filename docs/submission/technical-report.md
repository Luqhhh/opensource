# 1. 问题、用户与适用场景

开源项目的 API、返回结构或运行时版本发生变化后，教程中的代码可能仍然保留旧写法。使用者遇到错误时，往往需要在文档、源码和错误堆栈之间反复查找。维护者即使得到 AI 建议，也仍需判断补丁是否仅让错误消失，还是保留了示例原本要说明的行为。

例证面向 Python 开源项目维护者、教程作者与学习者，选择“可独立执行的 Markdown Python 示例”这一小范围切入。工具把定位失败、生成候选、保留检查、隔离复验和输出补丁连成一条可检查的工作流程。证据包括 TinyDB、more-itertools、MarkupSafe 的历史迁移、后续 Mistune/Werkzeug 项目留出，以及自编兼容性和 SDK 开发样例。真实案例固定历史文档与目标源码的不同版本，不代表当前上游文档存在缺陷；尚无访谈或用户耗时研究，不能声称已证明节省多少人力。

适用条件是 Linux、Python 3.10+、可用的 Bubblewrap 命名空间，以及用户明确选择的 `.py` 源文件。v0.1 执行环境限标准库与选定源码，不自动安装第三方依赖；不支持跨代码块自动状态推导、Notebook、多语言或通用恶意代码服务。

# 2. 方案与自主实现

整体流程：**文档与选定源码 → 代码块提取 → 隔离检查 → AI 修复候选 → 完整性检查 → 隔离复验 → HTML/JSON/补丁 → 人工审核。**

| 环节 | 已实现行为 | 对应实现 |
|---|---|---|
| 输入和提取 | 明确文档、源码及检查；提取普通围栏；保留原始内容摘要 | `config.py`、`extract.py` |
| 执行 | 只读挂载、网络隔离、超时与资源限制；环境不可用时停止 | `runner.py` |
| 候选来源 | 记录候选回放或本地 Ollama 调用；清晰记录来源 | `providers.py` |
| 修复审查 | 检查原断言结构和有限语法，拒绝破坏检查的候选 | `guard.py` |
| 多轮流程 | 每例最多 1–5 轮，反馈失败、拒绝与停止原因 | `pipeline.py` |
| 交付 | 转义后的独立 HTML、JSON 逐轮证据、统一补丁 | `report.py`、`cli.py` |
| 评测 | 冻结输入、检查基线、修复、临时应用补丁并复查完整文档 | `benchmark.py` |
| 检索与诊断 | 任务/调用对象检索，固定标准库 API 索引，宿主失败分类；默认 legacy，可选 semantic-v2 | `context.py`、`stdlib_index.py`、`providers.py` |
| 受控对比 | 固定模型、案例、提示词、源码摘录与预算；开发/留出分离、方法锁、配对五组及终态复核 | `study.py`、`semantic_study.py` |

上述应用层模块、配置格式、状态约定和案例夹具在本仓库实现，开发中使用了生成式 AI 辅助，不能笼统描述为全部人工独立编写。项目没有训练基础模型，也未修改 Python、Bubblewrap、Ollama 或 Qwen 权重。第三方项目的能力及权利不归入团队自主成果，具体边界见附件。

原文档和源码只读。工具输出补丁，使用者在审核后自行应用，不直接覆盖工作区。评测命令可以自动将补丁应用到一次性副本，核对整个文档重新提取后的结果。每轮候选只替换原代码块，不能修改源码、配置或 evaluator 管理的检查。每次复验始终相对原始断言检查，而不是相对上一轮已改写的代码。

# 3. AI 与开源资源如何发挥作用

开源模型 Qwen2.5-Coder 7B Instruct 经 Ollama 本地推理，根据原示例、周边文档、明确选择的源码和错误提出修改。当 SDK 参数或返回结构变化时，源码为模型提供当前接口信息。后续轮次可附上此前候选与反馈；外部检查代码和预期输出不进入请求，外部 evaluator 失败反馈隐藏检查细节。

默认修复策略保持 legacy；`--repair-policy semantic-v2` 是实时模型路径的可选升级。新版从目标源码检索任务与调用对象相关的原文，并在确认项目缺失导入时检索固定的 CPython 3.10.12 公开函数索引。索引通过 AST 从 153 个公开平面模块机械提取 999 个顶层函数签名/docstring，保留来源、摘要、完整许可及局部通知；不执行索引代码，不包含案例答案。更多开源信息的引入属于整体方法变化，不能当成反馈单项收益。

模型负责产生候选，工具负责实施有限的独立于模型输出的判断标准。原示例中的顶层断言或用户事先设置的行为检查，才可以作为行为证据；模型新增断言不能补足原本缺失的证据。无行为检查的示例即使运行成功，也只记为 `runnable_unverified`，其修复候选不能进入 `verified.patch`。

Bubblewrap 是实际执行隔离的关键开源组件，Python 标准库承担提取、调度和报告。仓库开放核心实现、测试和推理证据，使维护者可以复用或调整流程。这些资源分别参与模型推理、执行验证和开放协作，不只是普通开发环境的附带使用。

# 4. 改进点与相关工作

[Sybil](https://sybil.readthedocs.io/en/latest/) 已提供文档示例解析与测试集成；[Drift](https://github.com/pallaprolus/drift) 关注文档与代码漂移。例证在此问题域探索以下工程设计，不主张提出新的基础模型算法，也没有对这些工具开展效果优劣实验。

1. **将模型建议约束在可审核的补丁范围。** 只改代码块，保留原断言；跳过、可运行但未验证、候选失败和检查通过分开报告，避免把执行退出码等同于修复正确。
2. **把执行反馈与证据保存纳入修复流程。** 每轮保存候选、检查结果和停止原因；真实推理保存实际请求、响应、token 和耗时，失败与放弃也保留。
3. **用原始检查管理多轮候选。** 重复、耗尽、服务错误和缺少行为证据有明确停止条件；通过有限检查的最终候选才生成补丁，且原始输入保持不变。
4. **兼顾文档可合并性。** 补丁保留围栏缩进、换行风格和文件末尾状态，候选含关闭围栏时扩展外层围栏；检查补丁可应用后，再在一次性副本中复查。

以上为工作流和验证设计的改进。尚无用户研究、竞品受控实验或社区采纳证据，差异化描述不等同于领先性结论。

## 5.6 先冻结的三组模型对照

v1 案例在采集和参考候选验证阶段没有调用实时模型，也未用于本项目此前提示词调整。2026-10-13 已保存 `docs/evidence/real-projects-20261013/protocol.json`、输入/基线/源码摘录 SHA、实现快照及本地协议摘要，然后启动全部真实调用。公开上游文本可能存在于模型预训练中，因此“未见”仅指当时的本地提示词开发过程，而非训练数据去污染证明。

| 组别 | 模型可见信息 | 第 2–3 次请求 |
|---|---|---|
| direct | 原代码、周边上下文、初始错误 | 独立请求，不含前次候选或反馈 |
| source | 与 direct 相同，加自动选取的源码摘录 | 独立请求，不含前次候选或反馈 |
| source_feedback | 与 source 相同 | 加此前候选、运行/完整性反馈；隐藏外部检查细节 |

三组固定 Qwen2.5-Coder 7B Q4_K_M 摘要、Ollama 0.40.3、temperature 0.2、上下文 8192、生成上限 1024 token、超时 180 秒；源码摘录上限 12,000 字符。请求不含参考答案、checks、预期输出或修复记录。seed=17/29/43，每例后续请求 seed+1；最多 3 次调用，首次通过即停，无效生成仍计预算，基础设施故障记为不完整。

组别顺序轮换，保存全部请求、响应、失败、token 和耗时；最终候选需应用补丁并复查。相同最大调用/输出预算不等于实际输入 token 或耗时相同。5 个不同失败案例 × 3 个 seed 是**每组 15 个案例运行**，不是 15 个独立缺陷。

实验已完成全部 **27 个项目/组别/seed 单元、92 次真实请求**，`summary.json` 的 `complete` 为 true；最终模型摘要、提示词、源码、案例、检查、基线和协议复核均通过。以下每项修复数均要求候选通过冻结检查，并实际应用补丁后再次通过。

| 组别 | 首轮通过 | 预算内通过 | 请求数 | 输入 / 输出 token | 推理 / 全流程秒 |
|---|---:|---:|---:|---:|---:|
| direct | 4/15 | 7/15 | 35 | 24,926 / 4,513 | 139.97 / 148.71 |
| source | 8/15 | 9/15 | 28 | 129,525 / 4,177 | 145.18 / 153.83 |
| source_feedback | 8/15 | 8/15 | 29 | 140,668 / 4,669 | 150.15 / 159.06 |

每组 3 个健康对照 × 3 个 seed 的 9 次运行均保持通过且未调用模型。全流程秒为各单元累计，不含采集/冻结；未测功耗或货币成本。请求、候选、补丁复查位于 `docs/evidence/real-projects-20261013/runs/`，汇总见同目录 `summary.json`。

源码组比直接组多通过 **2 个案例运行**，输入 token 从 24,926 增至 129,525；反馈组 8/15 低于源码组 9/15，未带来净收益。按“至少一个 seed 通过”去重，三组案例覆盖均为 **3/5**，具体案例不同，不能声称覆盖扩大、成本更低、统计显著提升或普遍泛化。

`collate` 所有组均未修复；源码组把 TinyDB 默认表误改为 `drop_table('default')`，直接组虽修好默认表，却多次猜测不存在的 `remove_table`。反馈组 seed 29 使用正确删除 API 但多加 print，违反无输出契约，仍计失败。这类输出偏差与 API/行为错误应区分，不能事后放宽冻结检查。

MarkupSafe 已接受候选使用 `escape(value)` 或双重 escape，仅对固定 Markup 输入与显示检查有效，未证明一般输入保留 `soft_unicode` 语义。v1 按冻结检查记为**有限契约通过**，不能称通用迁移已解决；第 5.7 节另建新版检查，不追改此成绩。

协议摘要是本地误改检测，不是第三方预注册或时间戳认证。所选案例小且偏向可独立执行的历史迁移，源码采用固定摘录算法，结果也受其选择质量影响；有限检查通过不等于人工确认所有输入的语义等价。v1 冻结实验内部未据结果改题或择优报分；后续据这些结果改进的方法和评测另记为 v2 开发。

## 5.7 新版语义验证、开发迭代与项目留出

针对 v1 暴露的有限检查与失败，新建 `development_v2`，不改旧案例或追溯改分。开发集为 6 个迁移失败、3 个健康：MarkupSafe 新增可复用 `convert` 契约，检查普通/空/Unicode/HTML 字符串、str 子类、Markup 类型与 identity、数字、布尔、None 和自定义对象；TinyDB 增加表范围、多记录、重复调用、重建 ID 与持久化；`collate` 检查 key/reverse、重复项、稳定顺序、一次性迭代器及无限流的有限前缀。绑定与输出要求在模型可见上下文披露，新增任务明确标为评测者编写的语义适配，而非官方原文机械摘录。

同检查在旧运行时 **9/9 通过**；目标原始为 **6 失败、3 健康**；参考补丁修复 6/6 且健康 3/3 保留。**9 个格式合法的错误候选全部被外部语义检查拒绝，其中 8 个 stdout 仍相同。** 上述均为 0 模型请求的工程验证。复审也保留盲点：TinyDB 的一次 insert 已先清空查询缓存，因而现有序列不能独立证明 clear_default 的缓存失效；仅覆盖单实例 JSONStorage。MarkupSafe 未测试 C 扩展及全部对象异常行为；`collate` 未测试异常迭代器与大规模性能。详细复审记录见新版证据目录。

新版设计固定五组，legacy 默认生产路径不变；semantic-v2 为显式可选路径。实验中两种提示词/检索的组内首轮请求完全相同，分类只出现在后续历史：

| 组别 | 提示词与源码 | 后续请求 |
|---|---|---|
| legacy_source | 原提示词、原检索，12000 字符 | 独立采样 |
| legacy_feedback | 同 legacy_source | 通用执行反馈 |
| source_v2 | 新提示词、新检索，总计 6000 字符 | 独立采样 |
| generic_feedback_v2 | 同 source_v2 | 通用执行反馈 |
| feedback_v2 | 同 source_v2 | 通用反馈加宿主固定分类 |

模型、temperature、上下文与每次生成上限沿用第 5.6 节；每例最多 3 次调用，首次通过即停，失败与无效生成均计预算。开发集 seed=17；留出集为 17、29、43。固定最大调用/输出预算不等于输入 token 相等。source_v2 与 generic_feedback_v2 比较历史反馈，后者与 feedback_v2 比较分类；新旧方法之间还改变检索、提示词及标准库信息，不能归为单因子提升。

第一轮开发实验共 52 次请求，五组预算内均通过 **4/6**；legacy 两组首轮 3/6，v2 三组首轮 4/6。新方法修复 TinyDB 默认表但仍未满足通用转换契约，`collate` 五组都失败；反馈未增加预算内通过数。这些负结果完整保留在 `semantic-v2-development-20261013/`。

第二轮开发仅调整检索：过滤无关私有类/方法；原始错误确认项目缺失导入且匹配原代码时，才在固定 CPython 索引中检索标准库替代。默认 6000 字符分为项目 4000、标准库 2000，空余不回流；未触发时全额用于项目源码。不改 SYSTEM、开发输入或检查，第二轮另存目录，不能只挑选较好轮次报告。

# 6. 安全、权利与 AI 辅助开发说明

沙箱采用只读源码挂载、独立网络等命名空间和资源限制，清空环境，不挂载宿主 home 或凭据。命名空间不可用时返回阻塞状态，不回退到宿主执行。本地 Ollama 仅允许回环地址、禁用环境代理与重定向。HTML 对输入进行转义，报告不加载外部脚本。

这些措施不构成完整的恶意代码防护。示例和检查仍在同一进程，完成凭据只能发现部分提前退出，不能阻止主动伪造或同进程状态篡改；通过有限检查也不证明一般语义等价。当前用途限定为人工选择的开源示例和经审核的候选。请求及报告含用户选择的源码、文档，公开前需确认授权且无秘密与非必要个人信息。

2026-10-13 的开发使用对话式生成式 AI 辅助选题、规则梳理、架构、代码、测试、提示词与文档写作；本轮材料整理亦由 AI 辅助。已由自动化工具完成的工作包括运行测试、核对报告数据、保存推理记录、补丁复查和文档构建，这些不等同于团队成员已完成人工审核。

**待团队完成并记录：** 实际使用的辅助 AI 账号/服务与模型版本、参与成员及审核分工、关键代码与生成内容的来源/权利核查、对材料的修改记录、共同权利人的参赛授权。当前不宣称 AI 生成内容当然属于团队自主知识产权，不填写未经提供的成员经历、授权或外部成果。附件中的许可核验是资料记录，不能代替权利主体的确认。
