本报告依据用户提供的《附件1_AIC·AI开源竞赛规则及作品提交要求0812》组织，成果链接为 [ExampleProof 代码仓库](https://github.com/Luqhhh/opensource)。当前稿包含资源使用清单附件；团队审核、演示视频和报名系统提交尚未完成。报告不含参赛单位及指导信息。文中“通过”均受具体检查范围约束，不表示获得赛事认定。

# 1. 问题、用户与适用场景

开源项目的 API、返回结构或运行时版本发生变化后，教程中的代码可能仍然保留旧写法。使用者遇到错误时，往往需要在文档、源码和错误堆栈之间反复查找。维护者即使得到 AI 建议，也仍需判断补丁是否仅让错误消失，还是保留了示例原本要说明的行为。

例证面向 Python 开源项目维护者、教程作者与学习者，选择“可独立执行的 Markdown Python 示例”这一小范围切入。工具把定位失败、生成候选、保留检查、隔离复验和输出补丁连成一条可检查的工作流程。当前依据包括 TinyDB、more-itertools、MarkupSafe 三个真实项目的官方历史文档迁移案例，以及此前的自编兼容性和 SDK 开发样例。真实案例固定原始文档与目标源码的不同版本，不能理解为当前上游文档存在缺陷；尚未开展访谈或用户耗时研究，因此不声称已经证明节省多少人力。

适用条件是 Linux、Python 3.10+、可用的 Bubblewrap 命名空间，以及用户明确选择的 `.py` 源文件。v0.1 执行环境限标准库与选定源码，不自动安装第三方依赖；不支持跨代码块自动状态推导、Notebook、多语言或通用恶意代码服务。

# 2. 方案与自主实现

整体流程：**文档与选定源码 → 代码块提取 → 隔离检查 → AI 修复候选 → 完整性检查 → 隔离复验 → HTML/JSON/补丁 → 人工审核。**

| 环节 | 已实现行为 | 对应实现 |
|---|---|---|
| 输入和提取 | 明确文档、源码及检查；提取普通围栏；保留原始内容摘要 | `config.py`、`extract.py` |
| 执行 | 只读挂载、网络隔离、超时与资源限制；环境不可用时停止 | `runner.py` |
| 候选来源 | 记录候选回放或本地 Ollama 调用；清晰记录来源 | `providers.py` |
| 修复审查 | 检查原断言结构和有限语法，拒绝破坏检查的候选 | `guard.py` |
| 多轮流程 | 每例最多 1–5 轮，反馈失败、拒绝与停止原因 | `pipeline.py` |
| 交付 | 转义后的独立 HTML、JSON 逐轮证据、统一补丁 | `report.py`、`cli.py` |
| 评测 | 冻结输入、检查基线、修复、临时应用补丁并复查完整文档 | `benchmark.py` |
| 受控对比 | 固定模型、案例、提示词、源码摘录与预算；配对 seed、三组对照及完整终态复核 | `study.py` |

上述应用层模块、配置格式、状态约定和案例夹具在本仓库实现，开发中使用了生成式 AI 辅助，不能笼统描述为全部人工独立编写。项目没有训练基础模型，也未修改 Python、Bubblewrap、Ollama 或 Qwen 权重。第三方项目的能力及权利不归入团队自主成果，具体边界见附件。

原文档和源码只读。工具输出补丁，使用者在审核后自行应用，不直接覆盖工作区。评测命令可以自动将补丁应用到一次性副本，核对整个文档重新提取后的结果。每轮候选只替换原代码块，不能修改源码、配置或 evaluator 管理的检查。每次复验始终相对原始断言检查，而不是相对上一轮已改写的代码。

# 3. AI 与开源资源如何发挥作用

开源模型 Qwen2.5-Coder 7B Instruct 经 Ollama 本地推理，根据原示例、周边文档、明确选择的源码和错误提出修改。当 SDK 参数或返回结构变化时，源码为模型提供当前接口信息。后续轮次可附上此前候选与反馈；外部检查代码和预期输出不进入请求，外部 evaluator 失败反馈隐藏检查细节。

模型负责产生候选，工具负责实施有限的独立于模型输出的判断标准。原示例中的顶层断言或用户事先设置的行为检查，才可以作为行为证据；模型新增断言不能补足原本缺失的证据。无行为检查的示例即使运行成功，也只记为 `runnable_unverified`，其修复候选不能进入 `verified.patch`。

Bubblewrap 是实际执行隔离的关键开源组件，Python 标准库承担提取、调度和报告。仓库开放核心实现、测试和推理证据，使维护者可以复用或调整流程。这些资源分别参与模型推理、执行验证和开放协作，不只是普通开发环境的附带使用。

# 4. 改进点与相关工作

[Sybil](https://sybil.readthedocs.io/en/latest/) 已提供文档示例解析与测试集成；[Drift](https://github.com/pallaprolus/drift) 关注文档与代码漂移。例证在此问题域探索以下工程设计，不主张提出新的基础模型算法，也没有对这些工具开展效果优劣实验。

1. **将模型建议约束在可审核的补丁范围。** 只改代码块，保留原断言；跳过、可运行但未验证、候选失败和检查通过分开报告，避免把执行退出码等同于修复正确。
2. **把执行反馈与证据保存纳入修复流程。** 每轮保存候选、检查结果和停止原因；真实推理保存实际请求、响应、token 和耗时，失败与放弃也保留。
3. **用原始检查管理多轮候选。** 重复、耗尽、服务错误和缺少行为证据有明确停止条件；通过有限检查的最终候选才生成补丁，且原始输入保持不变。
4. **兼顾文档可合并性。** 补丁保留围栏缩进、换行风格和文件末尾状态，候选含关闭围栏时扩展外层围栏；检查补丁可应用后，再在一次性副本中复查。

以上为工作流和验证设计的改进。尚无用户研究、竞品受控实验或社区采纳证据，差异化描述不等同于领先性结论。

# 5. 真实推理与验证证据

## 5.1 数据类型与口径

原教程演示共有六个代码块：一个 Python 历史兼容性变化的自编重现、两个自制 SDK 失败样例、一个正常对照、一个因上下文不足而跳过的片段、一个没有行为检查的片段。修复分母为其中三个原始失败样例。六个片段不能写成六个真实开源缺陷，也不能将人工保存候选的回放写成模型实时推理。

真实模型证据位于 `docs/evidence/ollama-20261013/`。环境为 Python 3.10.12、Bubblewrap 0.6.1、Ollama 0.40.3、RTX 4070 Laptop GPU 8 GB；模型为 `qwen2.5-coder:7b`、Q4_K_M、约 7.6B 参数，运行上下文 8192，单并行请求，temperature 0，socket 超时 180 秒。模型 manifest 和安装包摘要见该目录的 `environment.json`。

## 5.2 已保存的真实调用

| 运行 | 轮数上限 | 已检查修复/原失败 | 请求数 | 输入/输出 token | 请求累计秒 |
|---|---:|---:|---:|---:|---:|
| 原提示词，single | 1 | 2/3 | 3 | 2440 / 248 | 12.9232 |
| 原提示词，multiround | 3 | 2/3 | 3 | 2440 / 248 | 7.4572 |
| 优化提示词，optimized | 3 | 3/3 | 3 | 1977 / 273 | 9.5299 |

原提示词两次运行中，模型对 `collections.Mapping` 导入失败返回空代码并放弃；其余两例通过原断言及外部检查。放弃会停止该例，因此增加轮数上限没有增加实际请求，也没有提升修复数。

在看到上述结果后，通用提示词增加“返回完整代码块”、依赖范围与允许使用标准库兼容接口的说明，并删除重复原始错误堆栈。没有注入该例正确导入、预写补丁或外部检查。优化后三例均在第一轮通过。输入 token 减少 463，约 19%；这只是这一批请求的 token 变化。

三次补丁均通过应用检查，并应用到一次性副本后重新运行。优化后副本结果为 4 个 `checked`、1 个 `skipped`、1 个 `runnable_unverified`，无失败。原输入未改写。报告保留原始请求、响应和放弃记录，可沿每一轮重查结论。

**解释限制：** 本小节提示词基于已见开发样例调整，这三次运行没有独立未见测试集，只支持流程可行性，不支持稳定成功率、跨项目泛化、多轮反馈增益或推理速度提升结论。首次冷启动、后续缓存和输出长度差异都影响耗时。另行冻结的新项目评测见第 5.5–5.6 节，不能与本组混算。

## 5.3 工程验证与可复现操作

工程验证的实际数量、日期与对应版本见 [验证记录](https://github.com/Luqhhh/opensource/blob/main/docs/validation.md)。核心测试与需要启用的真实沙箱集成测试分开记录，未执行的测试不得写成通过。测试涵盖路径约束、断言完整性、HTML 转义、模型协议模拟、超时、网络隔离、提前退出等。模型协议模拟和记录候选回放属于工程验证，不能增加真实模型样本数。

从仓库根目录运行以下命令。`check` 在已知失败样例上预期退出码为 1；回放成功不代表调用了模型。

```sh
python3 -m exampleproof scan examples/tutorial
python3 -m exampleproof check examples/tutorial --output artifacts/check
python3 -m exampleproof repair examples/tutorial \
  --proposals examples/tutorial/proposals.json --output artifacts/demo
```

在本机已安装指定模型和 Ollama 服务时，实时推理命令为：

```sh
python3 -m exampleproof repair examples/tutorial \
  --model qwen2.5-coder:7b --max-attempts 3 \
  --model-timeout 180 --output artifacts/live-recheck
git apply --check --directory=examples/tutorial \
  artifacts/live-recheck/verified.patch
```

运行与完整测试要求见仓库 README。命令不会自动下载模型。原提示词基线需要独立检出 commit `30fed20`；当前源码重跑只能验证当前实现。同名模型 tag 可变化，应核对 manifest 摘要；推理字节输出不保证在不同环境完全相同。

## 5.4 新增历史兼容性开发集与自动评测

`benchmarks/compatibility/` 增加六个已知 CPython API 变更的自编最小重现及两个健康对照，涉及 MIME Base64、墙钟计时、数组字节读写、HTML 实体、最大公约数和 JSON 数值精度。每例记录官方来源、删除版本及行为要求；只在当前 Python 3.10.12 重现，未在所有历史解释器运行。

已保存的工程回放证据显示：原始检查为六例失败、两例通过；记录候选回放为六例修复通过、两例保持通过；补丁应用到副本后八例均通过，健康对照未触发候选。另构造四个错误改法，均通过结构检查后被外部行为检查拒绝。这说明所设置的行为要求能识别这些特定错误，不能据此推算一般误修复率。来源、候选与检查共同准备且公开，所以回放成功不作为模型泛化证据。

`benchmark` 命令把输入快照、基线确认、候选修复、Git 补丁检查、临时应用和完整文档复查连接起来。其 `repair_rate` 只在评测证据完整且环境可用时给出，否则为 `null`；检查通过数不等于人工审核的语义正确数。新命令的指标与退出码详见 `docs/benchmark.md`，记录候选复现命令为：

```sh
python3 -m exampleproof benchmark benchmarks/compatibility \
  --proposals benchmarks/compatibility/proposals.json \
  --output artifacts/compatibility-replay
```

评测输出目录必须尚不存在，以免覆盖失败记录。该命令不调用模型。兼容性集的另三次真实运行使用与前述相同模型、硬件和上下文设置，完整证据保存在 `docs/evidence/compatibility-20261013/`：

| 设置 | 补丁复查通过/原失败 | 请求数 | 输入/输出token | 推理/全流程秒 |
|---|---:|---:|---:|---:|
| single，原提示词，上限1轮 | 2/6 | 6 | 3758 / 620 | 28.4550 / 29.8786 |
| multiround，原提示词，上限3轮 | 2/6 | 6 | 3758 / 568 | 16.6398 / 17.9656 |
| optimized，调整提示词，上限3轮 | 4/6 | 11 | 9292 / 1456 | 47.4288 / 49.8444 |

三次运行均保留两个健康对照且未对其调用模型，退出码均为1，表示仍有未通过案例。优化后补丁应用到副本得到六个通过、两个失败（其中六个通过含四个修复及两个健康对照），不能表述为六个失败全部修好。

新提示词根据本组已见失败记录调整，要求可以指出解决方案时返回完整代码，允许标准库导入和可调用别名替换，并强调保留类型、变换、副作用及格式；未写入特定案例答案。计时案例第一轮漏掉起始变量，第二轮调用顺序不当，第三轮才通过。这记录了真实的反馈修复过程，但其他条件及实际请求预算同时发生变化，不能将2/6至4/6单独归因于多轮策略。

未通过案例同样提供有用证据：Base64候选丢失MIME换行语义，被既定行为检查拒绝；HTML候选的文档输出本身正确，但删去了外部检查继续调用的 `decode_entities` 绑定，未满足该检查契约。后者既体现接口约束，也说明检查可能比仅输出正确更严格，不能一概称为错误输出。重复候选按既定停止条件终止，原始候选、反馈与失败结果均保留。

这组案例按已知标准库变更构造，候选和检查参与开发，且看到结果后进行了提示词适配。本组没有独立未见集、跨项目样本或盲审，4/6只是该次有限契约检查结果；更高token及时间开销亦如实报告，不主张一般修复成功率或速度提升。

## 5.5 三个真实项目的固定版本证据

`benchmarks/real_projects/` 新采集 TinyDB、more-itertools、MarkupSafe 官方 RST 或公开 API docstring 中的 8 个片段，含 **5 个迁移失败、3 个健康对照**。逐例保存文档位置与行号、两版源码提交、原始许可证、SHA-256、机械提取方式、声明的 setup、外部检查、原始失败、参考补丁及复查。未人为改坏正确示例，也没有用自造 SDK 替代上游实现。“三个项目”是本轮工作目标，不是赛事规则规定的数量。

| 项目 | 旧版 → 目标版 | 失败 / 健康 | 场景 |
|---|---|---:|---|
| TinyDB | 3.15.2 → 4.8.2 | 2 / 1 | 默认表清空、命名表删除、查询 |
| more-itertools | 5.0.0 → 9.0.0 | 2 / 1 | 排序归并、参数顺序、分块 |
| MarkupSafe | 1.1.1 → 2.1.5 | 1 / 1 | 安全文本转换、可空值转义 |

精确 commit 与逐例原文链接见 `benchmarks/real_projects/README.md`，各项目完整来源记录在 `provenance.json`。两版源码均原样映射至沙箱；MarkupSafe 使用官方纯 Python 分支，more-itertools 旧版所需 six 1.16.0 也固定源码与 MIT 许可证。无额外宿主运行依赖。

在同一检查下，原始片段运行于对应旧版库得到 **8/8 checked**；目标版本得到 **5 failed、3 checked**；预先编写的参考候选修复 5 例后，临时副本应用补丁并复查得到 **8/8 checked**。这些工程记录的模型请求数为 **0**，不算模型效果。原始失败与检查同时证明：例子在声明的旧环境下成立，新环境发生兼容性变化。

归一化处理只包括声明的 REPL 提示符移除、初始化组合、输出显示包装或必要导入，均可逐行核对原始文件。导出的补丁只适用于 `cases/*.md` 的规范化副本，不能直接应用到上游 RST/docstring；当前没有上游 PR、合入或维护者采纳证据。

## 5.6 先冻结的三组模型对照

新案例在采集和参考候选验证阶段没有调用实时模型，也未用于本项目此前提示词调整。2026-10-13 已保存 `docs/evidence/real-projects-20261013/protocol.json`、输入/基线/源码摘录 SHA、实现快照及本地协议摘要，然后启动全部真实调用。公开上游文本可能存在于模型预训练中，因此“未见”仅指本地提示词开发过程，而非训练数据去污染证明。

| 组别 | 模型可见信息 | 第 2–3 次请求 |
|---|---|---|
| direct | 原代码、周边上下文、初始错误 | 独立请求，不含前次候选或反馈 |
| source | 与 direct 相同，加自动选取的源码摘录 | 独立请求，不含前次候选或反馈 |
| source_feedback | 与 source 相同 | 加此前候选、运行/完整性反馈；隐藏外部检查细节 |

三组固定 Qwen2.5-Coder 7B Q4_K_M 模型摘要、Ollama 0.40.3、temperature 0.2、上下文 8192、每次最大生成 1024 token、超时 180 秒。源码摘录由固定算法从真实源码行生成，总预算 12,000 字符；三组均不接收参考答案、checks、预期输出、元数据或修复记录。seed 为 17、29、43，每例下一次请求使用 seed+1；所有组每个失败最多 3 次调用，首次通过即停。基础设施故障使该单元不完整，拒绝或无效生成内容仍消耗调用预算。

这保证相同的最大调用及输出 token 预算，不能称为实际输入 token 或耗时相同。按项目与重复轮换组别顺序，记录所有请求、响应、失败、token 和耗时；最终候选还需实际应用补丁并复查。5 个独立失败 × 3 个 seed 是**每组 15 个案例运行**，不能扩写为 15 个独立缺陷或项目。

实验已完成全部 **27 个项目/组别/seed 单元、92 次真实请求**，`summary.json` 的 `complete` 为 true；最终模型摘要、提示词、源码、案例、检查、基线和协议复核均通过。以下每项修复数均要求候选通过冻结检查，并实际应用补丁后再次通过。

| 组别 | 首轮通过 | 预算内通过 | 请求数 | 输入 / 输出 token | 推理 / 全流程秒 |
|---|---:|---:|---:|---:|---:|
| direct | 4/15 | 7/15 | 35 | 24,926 / 4,513 | 139.97 / 148.71 |
| source | 8/15 | 9/15 | 28 | 129,525 / 4,177 | 145.18 / 153.83 |
| source_feedback | 8/15 | 8/15 | 29 | 140,668 / 4,669 | 150.15 / 159.06 |

每组 3 个健康对照在 3 个 seed 下的 9 次运行均保持通过，未调用模型。表中全流程秒为该组各单元累计时间，不含一次性的采集/冻结；本机没有外部 API 按量账单，未测功耗或货币成本，token 与时间仅作为调用成本记录。全部请求原文、逐轮候选及临时补丁复查位于 `docs/evidence/real-projects-20261013/runs/`，汇总见同目录 `summary.json`。

本次源码组预算内比直接组多通过 **2 个案例运行**，但输入 token 从 24,926 增至 129,525，不能声称更省成本。执行反馈组没有带来额外净收益：8/15 低于源码组的 9/15，且输入 token 与耗时更高。按“至少一个 seed 通过”去重，三组覆盖的独立失败均为 **3/5**，只是具体通过的案例有所不同；不能把案例运行总数优势写成独立缺陷覆盖扩大。三次 seed 重复不增加独立缺陷数量，这些差异不是统计显著提升或普遍泛化的证明。

失败分析保留了不利结果：`collate` 在所有组均未修复，候选或误选排序关联函数、或引用未定义接口；源码组将 TinyDB 默认表清空误改为 `drop_table('default')`，外部检查发现默认表实际未清空。相反，直接组在默认表清空上通过，而在删除命名表时多次猜测不存在的 `remove_table`。这说明源码信息的收益并不对每个案例单调增加。

seed 29 的反馈组删除命名表候选已使用正确 API，但额外 `print(table.all())` 违反冻结的无输出契约，仍计为失败。这是输出格式约束失败，应与库 API 修复失败区分；其他行为已正确也不改题或事后放宽检查。工程上的“未通过”不一概等同于对所有任务语义都无效。

已接受的 MarkupSafe 候选也有明确范围限制：模型使用 `escape(value)` 或 `escape(escape(value))` 代替原转换，在本例固定的 Markup 输入及输出检查上有效，但没有采用参考候选的 `soft_str` 迁移，也未证明对一般输入保留 `soft_unicode` 的转换语义。本次仍按预先冻结的检查记录通过，并明确标注为**有限契约通过**；不能称为通用字符串迁移已经正确解决。后续加强检查应建立新版本评测，不能回改本次成绩。

协议摘要是本地误改检测，不是第三方预注册或时间戳认证。所选案例小且偏向可独立执行的历史迁移，源码采用固定摘录算法，结果也受其选择质量影响；有限检查通过不等于人工确认所有输入的语义等价。没有把本次结果回流用于修改同一批案例、检查或提示词后重新择优报分。

# 6. 安全、权利与 AI 辅助开发说明

沙箱采用只读源码挂载、独立网络等命名空间和资源限制，清空环境，不挂载宿主 home 或凭据。命名空间不可用时返回阻塞状态，不回退到宿主执行。本地 Ollama 仅允许回环地址、禁用环境代理与重定向。HTML 对输入进行转义，报告不加载外部脚本。

这些措施不构成完整的恶意代码防护。示例和检查仍在同一进程，完成凭据只能发现部分提前退出，不能阻止主动伪造或同进程状态篡改；通过有限检查也不证明一般语义等价。当前用途限定为人工选择的开源示例和经审核的候选。请求及报告含用户选择的源码、文档，公开前需确认授权且无秘密与非必要个人信息。

2026-10-13 的开发使用对话式生成式 AI 辅助选题、规则梳理、架构、代码、测试、提示词与文档写作；本轮材料整理亦由 AI 辅助。已由自动化工具完成的工作包括运行测试、核对报告数据、保存推理记录、补丁复查和文档构建，这些不等同于团队成员已完成人工审核。

**待团队完成并记录：** 实际使用的辅助 AI 账号/服务与模型版本、参与成员及审核分工、关键代码与生成内容的来源/权利核查、对材料的修改记录、共同权利人的参赛授权。当前不宣称 AI 生成内容当然属于团队自主知识产权，不填写未经提供的成员经历、授权或外部成果。附件中的许可核验是资料记录，不能代替权利主体的确认。
