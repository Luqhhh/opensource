# 规则对照与实际缺项

依据用户提供的《附件1_AIC·AI开源竞赛规则及作品提交要求0812.pdf》（5 页）。以下为 2026-10-13 的材料清点，不是赛事审核结论。规则页码按该 PDF 编号。

## 材料格式

| 规则要求 | 对应材料 | 当前状态 / 提交前动作 |
|---|---|---|
| p.4 名称≤20字 | `abstract.txt` 第一行 | 已拟定；构建脚本按字符计数 |
| p.4 简介≤300字，问题—方案—实现—效果—开放成果 | `abstract.txt` 第二段 | 已有；构建脚本按去空白字符计数，标点和拉丁字符也计入 |
| p.4 技术报告 PDF≤10MB，正文建议≤15页 | `technical-report.md` 与构建 PDF | 草稿；脚本严格按总页数≤15、大小≤10,000,000字节检查，包含资源附件 |
| p.4 参照技术报告参考大纲 | 规则给出的模板下载链接 | 参考大纲原文件未核对；提交前需按实际模板复核 |
| p.4 MP4，3–5分钟，≤300MB | `demo-script.md` | **只有脚本，MP4尚未录制**；导出后检查格式、时长、体积、音画 |
| p.2/p.4 开源及第三方资源使用清单，作为报告附件 | `docs/resources.md`；构建自动附录 | 已披露来源、版本、许可、方式、义务、自研边界、状态及开放方式；团队最终确认待完成 |
| p.4 成果链接在评审期持续有效，提供运行说明 | GitHub仓库与根README | 链接和说明已存在；最终成果版本和评审期访问可用性须复核 |
| p.4 总决赛答辩PPT，PDF格式 | 尚未制作 | 按晋级通知提交，不能描述为已完成初赛必交项 |
| p.4 可选佐证 | 测试记录、原始推理、补丁复查 | 可核验工程证据已保存；无用户反馈、上游合入等材料，不编造 |

## 建议完成顺序

新版证据入口为 [语义开发集](../../benchmarks/semantic_v2/development/README.md) 和 [两轮开发及项目留出总览](../evidence/semantic-v2-20261013/README.md)。开发检查的旧版 9/9 通过、参考修复 6/6、9 个负例全部拒绝属于 **0 模型请求的工程验证**，不能计入模型效果；其中 8 个负例显示输出仍正确。两轮开发各保留完整 52 次真实请求，五组预算内均 4/6，collate 与新版通用转换在 v2 组仍失败。新项目留出完成 30 单元/180 请求，终态复核及独立审计通过：五组均 0/12，健康各 6/6。12 为 4 个失败 × 3 个 seed，不是 12 个独立缺陷。新方法未取得留出修复收益，反馈不优于无反馈。

默认 legacy 不变，semantic-v2 需显式选择；五组最大调用预算相同，实际输入 token 不同，源码上下文上限分别为 12000/6000 字符。留出 source_v2 输入 token 为 95,778，legacy_source 为 160,488，减少 40.32%；两组成功数均为零，每成功修复成本不可定义，不能声称修复效率提升。

旧 [三项目案例集](../../benchmarks/real_projects/README.md) 和 [v1 对照结果](../evidence/real-projects-20261013/summary.json) 保留原字节、原成绩，使用 `verify_real_project_study.py --archived-only` 审计。已见案例不再称为留出；方法锁和 SHA 是本地记录，不是外部预注册。三项目是工作目标而非赛事规定数量；重复 seed 不增加独立缺陷，公开原文的预训练污染未知。所有实验通过数均不是赛事评分。补丁只对应规范化 Markdown，未形成上游 PR 或采纳证据。

1. 复核本轮代码、方法锁和完整留出汇总，固定最终提交版本；开发与留出分开报告，保留失败和成本，不混用新旧成绩。
2. 团队逐项审核AI生成内容、第三方资源和共同权利，留下真实审核与修改记录；若存在许可未知项，先调查并按实际情况更新。
3. 按演示脚本预演、录屏和剪辑，实测MP4时长与体积；所有画面坚持准确标记回放、历史证据或实时推理。
4. 获取并核对技术报告参考大纲，重新构建PDF；人工检查布局、匿名性、资源附件、证据链接与最终数字。
5. 按报名系统要求上传实际文件并留存回执；只有取得回执后才记录“已提交”。

构建或测试通过不会自动把以上人工审核、授权、录制和提交事项改为完成。
