# 按行修复：semantic-v4（2026-10-18）

1.5B 开发记录中，模型有时已收到正确接口的源码，仍重写整段示例，删掉数据准备或换掉无关操作。v4 根据源码提供可选替换，交给 AI 选择；没有合适替换范围时，让模型提出局部行修改。它是显式可选的实验策略，默认仍为 legacy。

## 改动与边界

- 对已观察到的缺失导入、名称、对象属性，从本次实际选中的源码函数中生成至多八个替换候选。检查函数所属类和可静态判断的调用参数，支持显式重新导出和已选中静态标准库摘录；不执行项目导入。候选保留原变量别名；AI 必须返回当前候选的 `choice` 整数编号及 `rationale`，工具按候选中的修改重建代码。候选只是未验证建议，仍可能语义错误。
- 没有候选时，模型收到原始行号，返回 `edits` 与 `rationale`。每个修改包含原始行号 `line` 和替换内容 `replacement`，最多八项。只重建被指定的行，其他行原样保留；替换允许多行以增加受限适配函数，空字符串表示明确删除该行。每次重试都以同一原始示例为准。
- 重复/越界行号、错误类型、无效 UTF-8、整体原样返回、超限候选和不存在的选项编号均拒绝，在原次数预算内反馈重试。一次有效修改中夹带原样行不会丢弃其他有效修改。已尝试过的源码候选从后续选项中排除；没有剩余候选时切换到按行修改。
- 完整候选继续经过 v3 的断言保护、公开名称检查、结构重复检测和隔离执行，再通过原外部行为检查。按行修改不能证明语义正确，也不阻止模型明确提出错误修改。
- 原始推理响应保留选择编号或行修改，请求中保留实际候选清单，报告同时保存重建的完整候选及差异。legacy、v2、v3 的输出协议保持原样。

源码摘录按标签与原文合计最多 4800 字符；额外的源码候选或所属类提示按 JSON 序列化最多 1200 字符。若公开异常确认选定项目的导入缺失、常规检索没有命中，可补充该声明模块的完整小文件，仍受 4800 字符限制。模型、调用次数和生成上限与 v3 配对。v4 同时改变候选构造、提示词和回答格式，因此组合比较不能单独证明某项机制的因果效果。没有硬编码项目名、接口替代答案或案例 ID，也没有将隐藏检查提供给模型。未增加 Python 运行依赖。

## 使用

需在 Linux/WSL 中准备 Bubblewrap 和本地 Ollama；不自动下载模型或安装服务。

```sh
python3 -m exampleproof repair examples/tutorial \
  --model YOUR_LOCAL_MODEL --repair-policy semantic-v4 \
  --max-attempts 3 --model-timeout 180 --output artifacts/live-semantic-v4
```

不能与 `--proposals` 回放混用。每次修复仍只导出补丁，不改被检查项目的原始文档。

与 v3 在同一批开发输入上比较：

```sh
python3 scripts/compare_repair_policies.py \
  benchmarks/semantic_v2/development/tinydb \
  benchmarks/semantic_v2/development/more_itertools \
  benchmarks/semantic_v2/development/markupsafe \
  --policies semantic-v3 semantic-v4 --model qwen2.5-coder:1.5b \
  --seeds 17 29 43 --max-attempts 3 --model-timeout 180 \
  --output artifacts/v3-v4-comparison
```

配对脚本沿用共同的 `repeat_penalty: 1.1`，普通 repair 命令没有该专用设置。输出目录必须新建；运行前冻结实现、输入、模型摘要和预算，结束后再次核对。三种子重复仍只有六个独立失败案例，属于已观察开发集的回归比较。

## 验证

261 项工程测试已在 WSL 中通过，隔离测试启用且无跳过。相对 v3 新增 19 项，覆盖行号稳定性、未修改内容保留、Unicode/换行、格式错误与长度限制、重试、原断言保护、原始证据、CLI、配对预算、源码候选的调用形状/所属类/显式重新导出/静态标准库证据，以及真实隔离执行后的补丁应用复查。推理响应均为模拟，工程测试不能作为模型成功率。

首轮只有按行修改时，v4 为 3/18、v3 为 2/18，正常对照均为 9/9。第二轮加入源码候选后重新冻结、独立运行并完成复算：v4 为 **15/18**、v3 为 **2/18**，正常对照均为 **9/9**，模型请求分别为 **31 / 52**。v4 覆盖五类缺陷各三次，grouper 参数迁移仍为 0/3。这证明本批已见开发案例的改善，没有证明未见项目上的总体提升。[完整结果、原始证据和复核入口](evidence/semantic-v4-1p5b/README.md)。此前 [v3 的四轮开发记录](evidence/semantic-v3-1p5b/README.md) 保持原样。
