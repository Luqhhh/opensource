## 当前范围与下一步

v0.1 支持 Python 标准库和明确列出的源码、Markdown 普通围栏示例、只读隔离执行、导入候选和本地 Ollama 修复适配、有限检查复验、JSON/HTML/补丁输出。生产默认仍为 legacy，实时模型调用可显式选择 `--repair-policy semantic-v2`，启用任务/调用对象检索与分类反馈；新版并不自动代替默认策略。

2026-10-13 本轮补充：自动评测与临时副本补丁复查、严格配置校验和 UTF-8 BOM 兼容、8例标准库开发基准（6历史重现+2健康对照）、4个刻意错误候选的检查，以及 [技术报告和演示脚本草稿](submission/README.md)。兼容性开发基准的真实模型验证由 2/6 增至 4/6，保留全部失败和调用成本；该结果来自已见案例上的提示词迭代，不能代表未见或跨项目成功率。[完整证据](evidence/compatibility-20261013/README.md)

本轮进一步完成 [三个真实项目的文档迁移案例](../benchmarks/real_projects/README.md)：TinyDB 3.15.2→4.8.2、more-itertools 5.0.0→9.0.0、MarkupSafe 1.1.1→2.1.5，共 **5 个迁移失败、3 个健康对照**。全部固定文档/源码提交、原文行号、许可、SHA-256 和提取方式；对应旧版源码的 8 例全部通过，目标版复现 5 例失败，参考候选回放并应用补丁后 8 例全部通过。参考回放模型调用为 0。这些是旧文档迁移至新版的真实上游例子，不是当前上游文档缺陷；“三个项目”是本次工作目标，不是赛事规定数量。

新案例未用于此前本地提示词调整，公开文本是否出现在模型预训练中未知。公平对照按 [冻结协议](evidence/real-projects-20261013/protocol.json) 固定模型摘要、案例、检查、提示词、源码摘录、调用预算和顺序，现已完成全部 27 个项目/组别/seed 单元、92 次真实请求，最终模型与输入复核通过。[完整结果](evidence/real-projects-20261013/summary.json)如下：

| 组别 | 首轮通过 / 预算内补丁复查通过 | 请求数 | 输入 / 输出 token |
|---|---|---:|---:|
| 直接修复 | 4/15 / 7/15 | 35 | 24,926 / 4,513 |
| 加入源码摘录 | 8/15 / 9/15 | 28 | 129,525 / 4,177 |
| 加入源码及执行反馈 | 8/15 / 8/15 | 29 | 140,668 / 4,669 |

每组 3 个健康对照 × 3 个 seed 的 9 次运行均保持通过。**5 个独立失败 × 3 个 seed 是每组 15 个案例运行，不是 15 个缺陷。** 本次源码组比直接组多通过 2 个案例运行，输入 token 显著增加；三组按“至少一个 seed 通过”去重后的独立失败覆盖均为 3/5，反馈组未显示额外收益。不能据此声称统计显著提升、通用成功率或跨项目泛化。失败记录完整保留，包括源码组将默认表清空误改为删除错误表名，以及某次反馈候选额外打印导致输出契约不符。MarkupSafe 的已接受候选仅通过固定安全文本输入的有限契约，不能据此证明一般字符串转换迁移正确。

针对上述问题，另建 [semantic-v2 开发集](../benchmarks/semantic_v2/development/README.md)，旧 v1 案例、检查和成绩均保持原样，审计使用 `verify_real_project_study.py --archived-only`。新开发集含 6 个失败、3 个健康，覆盖 MarkupSafe 通用转换的多种输入、类型与 identity，TinyDB 多记录、表范围和持久化，以及 collate 的 key/reverse、重复、稳定顺序与惰性。新增 callable 绑定任务明确标为评测者编写，所需绑定与输出契约均向模型披露，不称为官方原文机械摘录。

新版检查的历史正控制 9/9 通过，参考修复 6/6 且健康 3/3 保留；9 个格式合法错误候选均被外部语义检查拒绝，其中 8 个显示输出仍正确。以上均未调用模型。检查仍有限：TinyDB 一次 insert 已先使查询缓存失效，现有序列不能单独证明清空操作本身使缓存失效；尚不覆盖多进程存储、MarkupSafe C 扩展、异常迭代器等情形。

五组对照为 legacy_source、legacy_feedback、source_v2、generic_feedback_v2、feedback_v2。legacy 两组使用原提示词/检索与 12000 字符源码预算，v2 三组使用新提示词/检索与 6000 字符预算；两套方法各自组内首轮实际请求配对相同。每例至多 3 次调用；开发 seed=17，新项目留出 seeds=17/29/43。固定最大调用/输出预算不代表实际输入成本相同；新旧方法同时改变提示词、检索与标准库信息，不能把全部差异归为反馈效果。

两轮开发各完成 **52 次真实请求**，五组预算内均为 **4/6**，legacy 首轮 3/6、v2 首轮 4/6。第二轮加入固定 CPython 3.10.12 公开函数索引及私有 API 过滤；source_v2 输入/输出 token 为 **24,844/1,723**，legacy_source 为 **49,476/2,896**，实际请求分别 10/11 次。通用与分类反馈均未增加预算内通过数。TinyDB 默认表定位改善；collate 虽检索到 merge，候选仍缺少所需绑定而失败，MarkupSafe 通用转换在 v2 三组仍未通过，不能称已解决。

新项目 Mistune/Werkzeug 留出在方法锁后冻结并单独运行，完整完成 **30 单元、180 次请求**，终态复核与独立审计通过。五组首轮和预算内均 **0/12**，健康对照各 **6/6**，各调用 36 次；12 是 4 个独立失败 × 3 个 seed。source_v2 输入/输出为 **95,778/4,461 token**，legacy_source 为 **160,488/4,381 token**。输入减少 40.32%，但成功数均为零，每成功修复成本不可定义；**新方法未取得本次留出修复收益，反馈未优于无反馈**。完整五组成本与失败见 [新版实验总览](evidence/semantic-v2-20261013/README.md)。

开发与留出分开，方法锁是本地可核验记录，不是外部预注册、双盲或预训练去污染证明；锁定时第二轮开发尚未结束，此后未再修改方法。采集者意外接触部分通用提示词的边界另有披露。工程通过数不是赛事得分，不能将输入成本较低写成修复效果或泛化提升。

下一阶段优先级：

1. 团队审核全部失败与完整留出证据，区分行为错误、候选语法/绑定偏差及检查范围限制，固定最终提交版本。
2. 下一方法版本增加公开绑定要求的结构预检和更可行动的反馈，用新的留出案例检验收益，同时比较 token 成本；不修改本次冻结条件重新报分。
3. 补充独立进程行为核验、维护者反馈、外部复现与人工语义评价；采集规模和适用范围按实际证据报告。
4. 完成团队审核、报告模板核对与实际视频录制；未完成的人工或提交事项保持未完成状态。

本批补丁应用对象是机械规范化的 `cases/*.md`，不能直接应用到上游 RST/docstring，也不构成已提交或已合入上游 PR 的证据。

自动测试、PDF构建和候选回放不能替代真实项目采集、团队审核或视频录制；当前缺项见 [提交核对表](submission/checklist.md)。
