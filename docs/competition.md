## 当前范围与下一步

v0.1 支持 Python 标准库和明确列出的源码、Markdown 普通围栏示例、只读隔离执行、导入候选和本地 Ollama 修复适配、有限检查复验、JSON/HTML/补丁输出。

2026-10-13 本轮补充：自动评测与临时副本补丁复查、严格配置校验和 UTF-8 BOM 兼容、8例标准库开发基准（6历史重现+2健康对照）、4个刻意错误候选的检查，以及 [技术报告和演示脚本草稿](submission/README.md)。兼容性开发基准的真实模型验证由 2/6 增至 4/6，保留全部失败和调用成本；该结果来自已见案例上的提示词迭代，不能代表未见或跨项目成功率。[完整证据](evidence/compatibility-20261013/README.md)

本轮进一步完成 [三个真实项目的文档迁移案例](../benchmarks/real_projects/README.md)：TinyDB 3.15.2→4.8.2、more-itertools 5.0.0→9.0.0、MarkupSafe 1.1.1→2.1.5，共 **5 个迁移失败、3 个健康对照**。全部固定文档/源码提交、原文行号、许可、SHA-256 和提取方式；对应旧版源码的 8 例全部通过，目标版复现 5 例失败，参考候选回放并应用补丁后 8 例全部通过。参考回放模型调用为 0。这些是旧文档迁移至新版的真实上游例子，不是当前上游文档缺陷；“三个项目”是本次工作目标，不是赛事规定数量。

新案例未用于此前本地提示词调整，公开文本是否出现在模型预训练中未知。公平对照按 [冻结协议](evidence/real-projects-20261013/protocol.json) 固定模型摘要、案例、检查、提示词、源码摘录、调用预算和顺序，现已完成全部 27 个项目/组别/seed 单元、92 次真实请求，最终模型与输入复核通过。[完整结果](evidence/real-projects-20261013/summary.json)如下：

| 组别 | 首轮通过 / 预算内补丁复查通过 | 请求数 | 输入 / 输出 token |
|---|---|---:|---:|
| 直接修复 | 4/15 / 7/15 | 35 | 24,926 / 4,513 |
| 加入源码摘录 | 8/15 / 9/15 | 28 | 129,525 / 4,177 |
| 加入源码及执行反馈 | 8/15 / 8/15 | 29 | 140,668 / 4,669 |

每组 3 个健康对照 × 3 个 seed 的 9 次运行均保持通过。**5 个独立失败 × 3 个 seed 是每组 15 个案例运行，不是 15 个缺陷。** 本次源码组比直接组多通过 2 个案例运行，输入 token 显著增加；三组按“至少一个 seed 通过”去重后的独立失败覆盖均为 3/5，反馈组未显示额外收益。不能据此声称统计显著提升、通用成功率或跨项目泛化。失败记录完整保留，包括源码组将默认表清空误改为删除错误表名，以及某次反馈候选额外打印导致输出契约不符。MarkupSafe 的已接受候选仅通过固定安全文本输入的有限契约，不能据此证明一般字符串转换迁移正确。

下一阶段优先级：
1. 团队审核本次固定来源、有限检查契约及全部对照结果，区分行为错误、输出格式偏差与检查范围限制。
2. 围绕实验暴露的失败扩展案例与独立进程行为核验；新增数据与本次冻结集分开，避免追看结果后改题或挑选成绩。
3. 补充维护者反馈、外部复现与经人工确认的语义评价；采集规模和适用范围按实际证据报告。
4. 整理报告与演示。先保证真实证据，再扩展 Notebook、多语言、编辑器插件。

本批补丁应用对象是机械规范化的 `cases/*.md`，不能直接应用到上游 RST/docstring，也不构成已提交或已合入上游 PR 的证据。

自动测试、PDF构建和候选回放不能替代真实项目采集、团队审核或视频录制；当前缺项见 [提交核对表](submission/checklist.md)。
