## 评分与证据

| 评分项 | 分值 | 计划提供的证据 |
|---|---:|---|
| 问题与场景价值 | 15 | 文档失效的真实案例、用户操作成本、维护者反馈 |
| 创新性与方案设计 | 20 | 相对现有文档测试工具的诊断、最小补丁、复验改进 |

| 材料规范与表达 | 5 | 清晰完整的报告和演示 |

## 当前范围与下一步

v0.1 支持 Python 标准库和明确列出的源码、Markdown 普通围栏示例、只读隔离执行、导入候选和本地 Ollama 修复适配、有限检查复验、JSON/HTML/补丁输出。

下一阶段优先级：
1. 复现 5 个真实开源项目问题，决定第三方依赖环境的最小支持范围。
2. 接入一个实际可用的模型，保存原始输入输出及成本。对比同一模型单次修复与加入源码/执行反馈的效果。
3. 扩展到 3—5 个项目、20—30 个案例（目标，非当前成果）。按项目或版本划分开发集与未见评测集。
4. 多轮修复、反馈重试、逐轮证据及可用 token 计数已实现；继续设计独立进程行为核验，建立成功、误修复、误报、完整耗时与调用成本口径。
5. 整理报告与演示。先保证真实证据，再扩展 Notebook、多语言、编辑器插件。
