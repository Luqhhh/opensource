# v0.1 架构

本文保留源途 · RepoPath 的底层教程分析与示例验证架构。当前面向学习者的产品入口见[学习工作台](learning-app.md)，名称与兼容标识见[品牌说明](branding.md)。

项目级教程分析的新增入口与基线见 [next-stage.md](next-stage.md)。`project_input.py` 获取公开 GitHub 的固定提交快照或只读本地目录，`tutorial.py` 发现文档、源码及依赖声明，复用 AST/词项索引生成候选，再直接选择或由 AI 选择证据，输出未经验证的建议。`model_api.py` 提供 DeepSeek 与本地 Ollama 的有界 JSON 调用。`analyze` 不调用 runner，不生成已验证补丁。下述 v0.1 执行边界继续适用于原有 Python 示例验证链路；项目级 `analyze` 默认调用官方 DeepSeek HTTPS 云端 Flash 模型并使用规则检索，`--static` 显式关闭模型调用；`compare` 默认使用 Flash。缺少密钥时直接报错，不自动降级。旧 `repair` / `benchmark` 保持原有默认；Ollama 保持回环限制。

`tutorial_edits.py` 从已冻结原文导出有代码保护的文字审阅补丁；`tutorial_study.py` 在调用模型前冻结同一输入与方法，再运行两个上下文策略，并提供无模型调用的一致性审计。文字补丁与 Python 运行验证使用不同状态，片段位置按原文逐行核对。`compare` 不重读两次本地输入，不改变原始断言、检查或预期输出。

`extract.py` 提取围栏示例；`config.py` 读取输入清单与外部行为检查；`runner.py` 用 Bubblewrap 执行；`providers.py` 生成或导入候选；`guard.py` 检查断言完整性；`pipeline.py` 复验与汇总；`report.py` 输出报告。

`benchmark.py` 读取独立案例清单，冻结选定输入，验证原始状态，再执行修复、临时副本中的 Git 补丁应用和完整文档复查。报告分别保存三阶段证据；不符预期的基线不会进入模型调用，环境与模型服务错误不折算成修复率。评测输出必须新建，避免覆盖失败记录。详情见 [评测协议](benchmark.md)。

## 执行边界

- 不执行安装脚本，不自动安装依赖。仅复制用户明确选择的 Python 源文件，拒绝隐藏路径、父目录越界和符号链接。
- 沙箱挂载系统 `/usr`、`/lib`、`/lib64` 为只读；宿主 home、环境变量、凭据不挂载。项目源码及执行文件只读，临时写入位于 `/tmp`。
- 使用独立网络、PID、IPC、用户等命名空间，清空环境并移除 capabilities，限制运行时间、CPU、虚拟内存、文件大小和描述符。Python 启动后将 `RLIMIT_NPROC` 设为 0；v0.1 仅支持单进程、单线程示例。
- 不支持命名空间的环境返回 blocked，不自动降级到宿主执行。
- 退出码为 0 还不足以通过执行检查。setup、示例和外部 checks 全部正常返回后，harness 才写入每次随机生成的完成凭据；宿主通过原始文件描述符有界读取并校验。`os._exit(0)` 等提前退出会失败。凭据文件单独绑定，标准输出保持不变。
- HTML 转义所有示例、模型及异常文本，使用禁用脚本和外部资源的 CSP。
- 模型 HTTP 请求禁用环境代理及重定向，仅接受回环地址。候选文件最多 2 MB，单次模型响应最多 256 KB；响应结构与 token 数进行校验。
- 报告文件先写入输出目录中的临时文件再逐一替换，避免通过输出硬链接改写项目文件。每个文件的替换是原子的，三份报告不构成跨文件事务。
- 配置拒绝未知顶层和示例字段，避免 `check` 等拼写错误使检查静默失效。Markdown 的文首 UTF-8 BOM 只在解析视图忽略，摘要和补丁仍保留原始字节。

## 修复边界

模型只可建议替换代码块，不可修改源码、配置或外部检查。原始断言以 AST 结构比较，修复暂限直线执行的导入、赋值、调用和断言。通过运行但没有原始行为检查的候选不会进入通过验证的补丁。

2026-10-17 新增显式 `semantic-v3` 路径，其结构扩展适用于 v3 及派生的 v4：最多四个顶层局部适配函数，无装饰器或注解，参数默认值必须为常量，函数体仅局部赋值和末尾一个 return（可有 docstring）。原始断言仍必须完整保留在顶层，全部 AST 仍执行危险引用、双下划线和属性/下标写入检查。普通调用的副作用及同进程检查局限不因这项结构扩展而获得新的安全证明。

2026-10-18 新增 `semantic-v4`。对公开缺失接口异常，从本次选中的真实函数签名生成有限替换，过滤明显不合的所属类/调用参数，由模型选择编号；其他情况由模型返回最多八项原始行号及替换内容。工具重建完整候选，未指定的行原样保留。候选不保证语义正确，继续执行原 AST 保护和隔离行为检查。原始请求、模型的选择/修改及完整候选分别留存。legacy/v2/v3 继续接收完整代码。[细则与验证](semantic-v4.md)

2026-10-19 新增 `semantic-v5`。对示例阶段的公开 TypeError，以实际选中的源码签名为依据提出完整参数方案；每个输入只使用一次，保持原求值顺序和断言。静态使用线索仅调整排序，不代替语义检查。缺失接口候选另按名称和实际接收者排序，其他所属类仍保留。协议、源码位置、模型选择与完整重建候选分别记录；动态/歧义签名、星号展开等继续由原路径处理。[范围与验证](semantic-v5.md)

v3 另从公开上下文提取原示例已经绑定、且被明确声明为可复用 callable/function 的名称。候选缺少名称或将其直接绑定为常量/容器时，在沙箱执行之前拒绝并给出具体反馈。其余可调用性和一般语义仍依赖原有行为检查，静态名称检查不计作独立正确性证据。外部 checks、expected_stdout 和参考候选不进入提取逻辑。

v3 可使用候选在 setup/示例阶段出现的公开异常（returncode 21），分配新候选相关源码 1600、原始任务源码 3200 字符；合并时按原始行号消除重复。另用最多 1200 字符标注已选完整 API 签名的所属类/名称及原文签名，源码加索引总预算 6000。仅从明确选择的公开源码 AST 生成元数据，不推荐未选函数或读取私有错误细节。完整历史保留在报告，请求仅发送最近两轮；全过程按 AST 识别重复，不因空白、注释或引号差异重跑同一候选，原样返回已知失败的原代码会在执行前拒绝。legacy/v2 保留原比较和重复停止行为。

v3 请求使用 JSON Schema 约束两个必需的字符串字段 `code` 与 `rationale`；旧策略仍使用 `format: "json"`。结构约束不证明候选正确，服务响应仍须通过宿主字段校验和全部原有执行检查。缺字段等候选格式错误在原有次数预算内反馈重试；服务错误停止。先 v2 后适配的阶段策略曾作开发实验，但实测退步后已撤回，未保留在当前代码中。

每个失败示例最多尝试 1–5 轮，默认 1 轮。后续请求保留原始示例、源码和错误，并附此前候选、完整性拒绝原因及脱敏的复验反馈；不向模型发送 evaluator 检查代码或预期输出。每轮始终相对原始示例校验断言，采用原始 oracle 类型，模型新增断言不能补足独立证据。legacy/v2 遇到重复候选停止，v3 则可在原预算内继续，均不重复执行；legacy/v2 只规范换行，v3 使用 AST 结构，均不直接删除 Python 缩进。仅最终 `verified_repair` 候选进入文档补丁。

这不是完整的恶意代码防护或语义等价证明。Bubblewrap 依赖宿主内核安全，源码仍可能尝试影响同进程检查。完成凭据用于发现提前退出，不构成防止代码读取 harness、主动伪造凭据或篡改同进程状态的安全边界。通用恶意代码服务化、强资源配额和外部验证进程需要进一步设计。当前限定为人工选定的开源示例及经审核的候选。

## 可复现信息

JSON（schema 2）保存文档、源文件和配置的 SHA-256，原始代码、每轮候选、运行输出、检查类型、耗时、拒绝及停止原因和候选来源；文档与源码按 UTF-8 原始内容计算摘要，不归一化 CRLF。本地模型响应另记录模型名及 token 数。结果级 `proposal` / `after` / `diff` 表示最后评估的候选，完整历史见 `attempts`；重复轮保留此前结果，重复候选记录在最后一条 attempt。项目级 `repair` 汇总轮数、推理请求数及耗时；失败响应中的有效 token 计数也纳入统计，任一轮缺少计数时总量为 null。

成功候选的 `proposal.inference_evidence` 保存实际请求 payload 与完整解析后的 Ollama 响应 envelope；调用或解析失败时保存于 `attempt.inference_evidence`。无法解析为 JSON 对象的正文最多保留 256 KB，超限时标记 `response_truncated`。证据同时包含请求开始 UTC 时间、实际耗时与 socket 超时设置，不记录 HTTP headers、认证或宿主环境变量。报告写入时将孤立 Unicode surrogate 转成转义形式，避免异常响应令整份报告丢失。真实模型验证记录另保存安装包和模型 manifest 摘要。依赖锁文件、系统镜像摘要与跨项目评测仍待补充。
