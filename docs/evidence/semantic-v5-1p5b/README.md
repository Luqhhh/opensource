## 扩展项目重测

每轮另行比较历史 Mistune、Werkzeug 案例，合计四个失败和两个正常对照，各三种子。这是已经见过的历史案例重测，不能重新称为新的留出实验；输入和原检查均未改动。

三轮扩展重测中，两组均为 **0/12**，正常对照均为 **6/6**。第三轮两组请求均为 36 次；v4 输入/输出 token 为 94120 / 2750，v5 为 94801 / 2892。开发集的改善没有解决这些多步骤构造、渲染和状态修改问题，不能称为通用成功率提升。

## 协议与复核

- 首次推理前冻结每轮的 21 个实现/许可/配对脚本文件、输入和模型摘要；每个单元前后复核摘要，同轮按种子交替两组顺序。每组最多三次调用，temperature 0.2、num_ctx 8192、num_predict 2048、repeat_penalty 1.1，seed 随完整尝试序号递增。普通 repair 命令没有这项专用 repeat_penalty 设置。
- 模型只接收原代码、公开说明、源码证据和经过过滤的失败反馈。候选构造与排序不读取隐藏检查、预期输出或参考补丁。原始项目、固定索引、断言、检查和此前证据保持原样。
- 结果经过基线、修复、临时副本应用补丁和完整文档复查。279 项工程测试在 WSL / Bubblewrap 中通过且无跳过，工程测试的模型回答为模拟，不能计为真实模型成绩。
- `audit.json` 直接从保存的三阶段报告复算结果、token 和调用次数，核对真实源码摘录并从原始模型响应重建候选；不会执行候选或归档代码。第三轮开发与扩展使用同一份实现，最终 `method-match.json` 核对逐文件摘要。
- v4 与 v5 同时存在候选构造、排序、提示词和输出协议差异，不是单因素消融。开发案例已见、样本很小，不能估计通用修复率。固定 seed 也不保证 GPU/Ollama 逐字节确定；第一轮同一公开接口请求出现不同回答的记录保留。
