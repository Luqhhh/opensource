## 协议与验证范围

- 本地模型为 Qwen2.5-Coder 1.5B Q4_K_M，Ollama 0.40.5，WSL Python 3.12.3 / Bubblewrap 0.9.0。模型清单摘要为 `d7372fd828518a4d38b1eb196c673c31a85f2ed302b3d1e406c4c2d1b64a0668`；安装文件再次逐项核对大小和 SHA-256。
- 每轮在首次推理前冻结实现、来源输入、案例、模型摘要及生成配置；两组均使用 temperature 0.2、num_ctx 8192、num_predict 2048、repeat_penalty 1.1。seed 随完整尝试序号递增，按种子交替策略顺序。普通 repair 命令没有这项专用 repeat_penalty 设置。
- 生成仅使用公开说明、原代码、实际选中的项目/静态标准库源码及过滤后的执行反馈。源码候选不是参考补丁；按真实签名构造，经过静态过滤后仍可能错误。模型决定候选编号，最终由原有检查验证。没有读取隐藏检查、预期输出或参考答案来生成候选。
- 两组使用相同原始断言、外部行为检查、隔离环境、生成和调用上限。结果必须经“基线 → 修复 → 临时副本应用补丁 → 全部文档复查”确认。正常示例不调用模型。原始项目、固定索引、检查和历史记录保持原样。
- `audit.json` 独立从三阶段报告重新计数，核对请求预算、种子、候选重建、输入和实现摘要。261 项工程测试通过、隔离测试启用且无跳过；其中模型响应为模拟，不计入上述真实修复率。
- 当前核心实现及配对脚本与第二轮冻结的 21 个文件逐项一致，见 `method-match.json`。组合策略同时改变候选构造、提示词和返回协议，不是单因素消融。此次调优看过全部开发案例，没有新的未见项目结果，也没有改变默认 legacy 策略。
