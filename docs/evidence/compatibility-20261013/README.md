所有运行保留原始失败和原始候选；没有人工改写模型补丁。案例代码、描述、外部检查与元数据在实时调用前冻结，模型可见的案例描述未包含正确替代 API 或修复步骤。外部检查、预期输出、元数据及回放候选不会发送模型。观察前两次结果后，仅调整通用系统提示词；因此优化后的成绩属于开发集迭代。

## 优化与失败分析

旧提示词下，模型经常在理由中写出可用替代方案，却返回空代码。新提示词明确：允许更新标准库导入和可调用别名；空源码列表不妨碍标准库修复；能够识别可靠方案时返回完整可执行代码，并保留类型、变换、副作用及输出格式。没有在提示词加入案例特定API、预写补丁或外部检查内容。两版实际系统提示词均保存在各次 `repair/report.json` 的请求中。

- **计时案例：** 优化后第1轮漏掉 `started`，第2轮把开始计时放到睡眠之后，第3轮调整顺序后通过检查和补丁复查。这是一次实际发生的反馈后成功记录，不能单凭此例推出稳定多轮收益。
- **数组、最大公约数、JSON：** 优化后各在第1轮通过既定检查，补丁复查通过。JSON保留Decimal解析选项。
- **Base64：** 模型选择的编码接口丢失MIME换行，虽可执行但被行为检查拒绝；后续重复候选触发停止，未写入补丁。
- **HTML：** 模型已正确解码示例文本，但删除了外部检查复用的 `decode_entities` 绑定；按当前检查契约仍未通过。不能把这个结果扩大解释为文本解码功能本身错误；它显示了检查契约和重构形式的限制。后续候选重复，未写入补丁。

优化同时改变提示词和实际调用预算（6→11），总token和耗时上升。没有独立的未见集、重复种子实验或相同预算的多轮消融，不能把4/6解释为泛化率，也不能单独归因于多轮机制。同温度下前两次生成也不完全一致；温度0不保证环境间逐字一致。冷启动、缓存和输出长度会影响耗时，本次没有速度收益结论。

另有 [4个刻意错误候选探针](../../../benchmarks/compatibility/evidence/negative.json)，分别破坏MIME换行、包含睡眠的计时、数组追加和Decimal精度。四例均通过结构检查后被外部检查拒绝；它们不是抽样模型输出，不能作为通用误修复率。

## 复现与证据位置

在仓库根目录启动已有模型服务后执行，使用尚不存在的输出目录：

```sh
python3 -m exampleproof benchmark benchmarks/compatibility \
  --model qwen2.5-coder:7b --max-attempts 3 --model-timeout 180 \
  --output artifacts/compatibility-live-recheck
```

当前源码使用完善后的提示词。复现原提示词需从 `single/repair/report.json` 中恢复实际请求的 `system` 内容；不得把当前提示词重跑称为旧基线。回放模式用 `--proposals benchmarks/compatibility/proposals.json` 替换 `--model`。

每次运行包含 `baseline/report.json`、`repair/report.json`、`repair/verified.patch` 和 `patched/report.json`，相应HTML可离线查看。报告保存模型返回的错误解释，即使其中把弃用版本说成移除版本；这些模型理由不是经核实的历史事实，正式来源以案例元数据为准。

[unittest.txt](unittest.txt) 是本轮完整118项测试记录，包含14项真实沙箱测试，无跳过。原始项目文件保持只读。补丁复查复用原有行为检查，不是一般语义等价证明或独立进程验证器。
