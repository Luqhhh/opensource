# Qwen2.5-Coder 1.5B 自动修复开发记录

本轮完成了真实本地模型调用、Bubblewrap 隔离执行、补丁应用及原检查复验。最终保留的实现与第三轮冻结的 21 个实现/许可文件逐字节一致，见 [方法核对](method-match.json)。最终工程验证为 [242 项通过、零跳过](validation.json)，工程测试不计入模型修复数。

**结论：结构化修复能力已经实现，小模型的整体收益仍不稳定。** 当前版本单轮比较为 v3 3/18、配对 v2 2/18，但两者只各自修好一类不同的缺陷；v3 调用更多，且旧策略在重复实验中为 2～3/18。因此不能将此记录描述为稳定、显著或普遍的成功率提升。默认 legacy 未改变，v2/v3 保留为显式选择。

## 当前实现对应的结果

六个已观察开发缺陷，每个运行种子 17、29、43；重复种子不是新缺陷。每组另有三个健康案例，每个种子重复一次。以下分母 18 是修复试次，独立失败案例数为 6。

| 指标 | 配对 v2 | v3（当前实现） |
|---|---:|---:|
| 补丁应用后确认修复 | 2/18（11.1%） | 3/18（16.7%） |
| 曾成功修复的独立缺陷类型 | 1/6 | 1/6 |
| 健康对照保持通过 | 9/9 | 9/9 |
| 模型请求数（包括失败/重复候选） | 42 | 52 |
| 输入 token | 116,582 | 141,794 |
| 输出 token | 6,304 | 7,593 |

逐题通过次数：

| 开发案例 | 配对 v2 | 当前 v3 |
|---|---:|---:|
| TinyDB：清空默认表且保留其他表 | 0/3 | 0/3 |
| TinyDB：只删除指定命名表 | 2/3 | 0/3 |
| more-itertools：可复用惰性排序合并 | 0/3 | 0/3 |
| more-itertools：分组与填充值 | 0/3 | 0/3 |
| MarkupSafe：原显示示例回归 | 0/3 | 3/3 |
| MarkupSafe：可复用转换函数契约 | 0/3 | 0/3 |

MarkupSafe 的成功只说明原显示案例通过有限检查，不证明通用转换契约已经解决。新策略在命名表案例上退步，不能只展示总数而隐藏该取舍。完整数据见 [当前比较](summary.json) 与 [独立复算](audit.json)。

## 运行条件与证据范围

- 本地模型为 `qwen2.5-coder:1.5b`，Q4_K_M；manifest SHA-256 为 `d7372fd828518a4d38b1eb196c673c31a85f2ed302b3d1e406c4c2d1b64a0668`。各权重文件的实测摘要保存在 audit.json；模型权重不随证据分发。
- Ollama 0.40.5，WSL Python 3.12.3，真实 Bubblewrap，RTX 4060 Laptop GPU；环境记录位于压缩包根目录。安装包、每个模型文件均已校验摘要。
- 完整比较均为每失败案例最多 3 次调用、每次最多 2048 输出 token、num_ctx=8192、temperature=0.2、repeat_penalty=1.1；seed 随尝试递增，两组一致，种子间交替顺序。第一次中止轮未显式设置重复惩罚，不能与后续完整轮混算。
- 当前 v3 仅使用公开任务、明确选择的源码及脱敏反馈。隐藏检查不参与生成要求、检索或提示；原断言、检查、期望输出和历史留出材料未改动。仅第一条通过原检查且补丁复查通过的候选计数。
- 普通 repair 的默认生成配置与配对入口不同；这些数值仅适用于所保存的协议，不代表默认 legacy 或任意调用配置。
- 方法在这六个已观察开发案例上反复调整，不能宣称新留出、随机抽样、跨项目普遍效果或某个单独组件的因果收益。历史 7B 结果另行保存，不能替换成这里的 1.5B 结果。延迟包含缓存/冷启动影响，不作速度优劣结论。
